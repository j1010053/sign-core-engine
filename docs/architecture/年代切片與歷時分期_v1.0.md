# 年代切片與歷時分期 —— 方言群不是分期(v1.0)

> **狀態:已裁定並實作(擁有者 2026-08-11)。本檔 §1 是 P72–P74 的權威。**
> 這不是規格擴充,是把一個**被混在一起的兩個問題**拆開——舊實作用親子邊算
> 「方言群」,而方言是共時概念。
>
> 承《演化圖本體論》§6.2(方言連續體 = 樹上一組互通度高於某閾值的鄰近點;
> 閾值由觀察者/UI 設定,資料層不做離散判斷)、修補04 增修 A(State 是撰寫時
> 輸入,`time` 為自由字串)、P61(全 parent merge)。
>
> **與既有編號決策無衝突**:P72–P74 不覆寫、不廢止任何既有 P/R/I 決策。
> §6.2 的「鄰近點」原本只有一種讀法(邊相鄰),現在有兩種——分別屬於兩個
> 函式,見 P72。

---

## 1. 決策(P72–P74)

### P72 —— 方言群是共時概念,與歷時分期**分離為兩個函式**

「方言」預設同時存在;**母語言與子語言不可能同時出現**。故沿親子邊算出來的
分群**不是**方言群,而是**歷時分期**。兩者拆成兩個函式,各自回答一個問題:

| 函式 | 比什麼 | 範圍 | 答什麼 |
|---|---|---|---|
| `periods` | 主幹邊(親↔子) | 全圖,N−1 次 | 何時該說它變成另一個語言了 |
| `dialect_groups` | 切片內**任意兩點** | 一個年代切片(P73) | 這個時代誰跟誰互通 |

§6.2 的「樹上一組互通度高於某閾值的**鄰近點**」因此有兩種讀法,各歸一個函式:
`periods` 讀成**邊相鄰**(距離 1),`dialect_groups` 讀成**同一個切片之內**。
沿主幹邊切出來的結果與演算法**原封不動**保留,只把名字改對。

### P73 —— 年代切片 = 演化圖的**反鏈**;判準是拓撲,不是 `time`

一個年代切片是一組**同時存在**的語言,其可判定內容為:**沒有任何成員是另一個
的祖先**(反鏈)。切片**預設為葉節點**(現存語言),其餘由呼叫端指定並驗證。

**不得改用 `EvolutionState::time` 判斷。** 該欄位是自由字串,且修補04 增修 A
明訂「絕對年代只是給人看的標註……沒有任何運算依賴它」;以它切片就得處理
「A 是 B 的祖先卻標了較晚年代」這種與圖拓撲矛盾的資料。走拓撲,那條理由繼續
成立,`time` 維持純標註。

違反反鏈的切片**必須拒絕**(`SLICE_NOT_AN_ANTICHAIN`),不得默默接受——接受
就是回到「母語言與子語言同群」,而那正是 P72 要消滅的東西。

### P74 —— 並存判準**只看主幹邊**;引用邊不構成祖裔

判斷「能否同時存在」時,只有主幹邊(`parents[0]`)算祖裔關係。引用邊
(donor / 合併)**不算**:克里奧爾與它的來源語**確實會並存**(海地克里奧爾與
法語),把引用邊當祖裔會把這種真實情形判成不可能。

這與分群「只看主幹邊」(引用邊不是世系鄰接)是同一條原則的另一面。

## 2. 問題

`TreeEdgeCut` 比的是**親子邊**——跨時間的比較——結果卻叫「方言群」。於是一條
純鏈狀的專案(一個語言一路演化)會得到:

```
古英語 ──> 中古英語 ──> 現代英語        舊輸出:2 個「方言群」
```

那三者不是方言,是**歷時階段**。真正的方言分群在這張圖上的答案應該是**恆為
一群**:任何時刻只有一個語言活著。

**母語言與子語言不可能同時出現**——這是整件事的判準。

## 3. P72 的落地:兩個函式

| 函式 | 比什麼 | 範圍 | 答什麼 |
|---|---|---|---|
| `periods` | 主幹邊(親↔子) | 全圖,N−1 次 | 何時該說它變成另一個語言了 |
| `dialect_groups` | 切片內**任意兩點** | 一個年代切片 | 這個時代誰跟誰互通 |

沿主幹邊切出來的東西本身有用,它只是**不叫方言群**。故 `periods` 保留原演算法
與原語意(`TreeEdgeCut` 原封不動),只把名字改對;`DialectGroupingStrategy`
更名為 `PeriodizationStrategy`。

## 4. P73/P74 的落地:切片

年代切片 = 圖的**反鏈**(antichain):沒有任何成員是另一個的祖先。

**不用 `EvolutionState::time`。** 那是自由字串,而且該欄位的註解明說「絕對年代
只是給人看的標註……**沒有任何運算依賴它**」;若改用它切片,就得處理「A 是 B 的
祖先卻標了較晚年代」這種與圖拓撲矛盾的資料。走拓撲,那條理由繼續成立,`time`
維持純標註。

**預設切片 = 葉節點**(`Slice::contemporary`)——唯一不必問使用者就算得出來的
那個,也就是「現在還活著的語言」。其他切片由 `Slice::new` 建,**驗證反鏈**並在
違反時回 `SLICE_NOT_AN_ANTICHAIN`:不驗的話,使用者把拉丁文和法文放進同一個
切片,就會回到舊實作那個荒謬,而那正是切片要消滅的東西。

### 4.1 祖裔只算主幹邊(P74)

引用邊(donor / 合併)**不算**祖裔。克里奧爾與它的來源語**確實會並存**
(海地克里奧爾與法語);把引用邊當祖裔會把這種真實情形判成不可能。這與模組
既有的「只看主幹邊」是同一條原則。

## 5. 保留下來、沒有被解決的三件事

1. **群 = 連通分量,不是團。** 兩個函式都用 union-find,群內可以存在一對彼此
   低於閾值的成員。要「群內兩兩皆通」是**團**語意,那是另一個演算法,且無法
   用 union-find 表達。
2. **切片內任意對仍可能因收斂而併群。** 舊模組說明拒絕「任意 pair」的理由是
   收斂(非同源卻變像)在本體論裡沒建模;那條理由針對**全域**任意對,切片內
   只是把它**限縮**,沒有解決。結果該讀成「現在看起來多像」,不是「同源」。
   語言聯盟仍未建模(見《接觸痕跡與語言聯盟 v0.1》)。
3. **平行創新會低報互通度。** 對齊鍵是 `SignId`/`RuleId`,兩條分支各自新增的
   東西 id 不同,故「兩邊做了同一件事」被算成一生一滅。實測:兩個兄弟各做
   **完全相同**的九條音變,彼此互通度 `0.1429`,比各自對父的 `0.5714` 還低。
   族譜角度對(獨立造出來的同形詞不是同源詞),互通度角度錯。這繼承自 §6.2
   把互通度定義成 diff 的派生函數,**要修得動 §6.1 的「以 id 對齊」**,擁有者
   已裁定暫不動。

## 6. 成本與尚未做的事

`dialect_groups` 這一版是 **`C(L,2)` 次**互通度計算(`L` = 切片大小),
**不做稀疏化**。實測每次比較約 `0.8 µs × 詞數`(release);400 詞、50 個語言的
切片約 `1225 × 0.32 ms ≈ 0.4 s`,而且這是**互動路徑**上的成本(桌面端閾值是
slider,`IpcHandle::grouping` 目前**無快取**)。

已評估、尚未實作的稀疏化(前兩者**不損失精確度**):

1. **路徑上界剪枝**:集合三角不等式 `changed(A,B) ≤ changed(L,A)+changed(L,B)`,
   而右邊可由本來就要算的邊 diff 前綴累加;每對 O(1),只有上界跨閾值的才真算。
   需要 measure 提供一個**可選**的界(`optimistic_bound`),放在 measure 上而非
   引擎裡,§6.4 不破。
2. **union-find 剪枝**:依上界排序,已同群的對直接跳過。**只在連通分量語意下
   成立**;團語意下每對都得算。
3. MinHash 草圖、抽樣:近似,要在結果上標記。

另需:`grouping` 加快取(key = view + 閾值 + 圖版本)、reach 索引 per-document
memoize(實測佔每次比較的 **27%**)。
