## 1. 現況(已落地,不重畫)

`conlang-persistence`(P60/P64)已實作:

```
<store root>/
  format                  "conlang-evolution-store/v1\n"    validate_format 把關
  objects/<sha256>        內容定址:global／trait／sign／identity／changeset 共用
  nodes/<node-id>/
    manifest              immutable,進 node-v2 雜湊
    edges                 immutable,進 node-v2 雜湊
    config                mutable,**雜湊外**(NodeConfig{label, preferences})
    annotation/           mutable,**雜湊外**
```

`manifest` = `{schema, source_sha256, identity_sha256, globals, traits[], signs[], identities, nativization}`。
immutable 檔以逐位元比對把關;`save` 只更新 `config`。

套件側已有的機制(**不必重造**):

| 元件 | 現況 |
|---|---|
| package 宣告 | `config/package.conf`:`kind`/`name`/`version`/`requires`/`code`/`data`/`priority`/`rule_namespace` |
| 依賴邊 | `LibraryPackage.requires: Vec<LibraryId>` |
| 遞移解析 + 環偵測 | `LibraryCatalog::visit()` 三色標記 DFS,回報 `DependencyCycle(a -> b -> c)` |
| 決定性排序 | `sort_same_layer` + kind rank + priority |
| 衝突檢查 | 重複 trait/sign、kind 不符、exports、rule namespace |
| 內容雜湊鎖 | `LibraryLock{package, version, digest}`,`digest = sha256_hex(package_lock_content(..))` |

**缺的只有兩件**:import 表沒有持久形式(且 `LibraryId` 不帶 version);
`LibraryCatalog` 只有 `embedded()` 一個入口,吃編譯期常數陣列 `EMBEDDED_PACKAGES`。

## 2. 已裁定事項

### R1 — 專案根 == store 根
`format` 留給 store(其格式版本是 store 自己的事);專案標記與 import 表進 `project.toml`。
persistence 零改動。

### R2 — 覆寫層的粒度與繼承
- 專案級覆寫住 `<project>/data/`;
- per-node 覆寫走既有 `nodes/<id>/config` 的 `preferences`(**雜湊外**);
- **正式放棄**《統計先驗與抽樣引擎》§2 的「覆寫層可 diff、被子語言繼承、被 D 快照」。

理由:2.0 的節點是 immutable snapshot,凡進 `manifest` 者必須可由 `PrimitiveEdit` 重建
——而那等於承認它是語言內容,與裁定 W 衝突。繼承語意已由 `EvolutionGraph` 的
parent 邊承擔,覆寫層不需要自己再做一套。

### R3 — import 表 + 找尋 + lock

**① import 表**(`project.toml`)只宣告**直接依賴**;遞移依賴由各 package 的
`requires` 展開,走既有 `visit()`。

**② 找尋順序**
```
1. <project>/packages/<name>/        vendored,最高優先
2. <user data dir>/packages/<name>/  使用者安裝的共享 package
3. 隨引擎發布的 package               std:* / natural:*(見 R7′:它們只是「找得到」,不是「自動載入」)
```
**不做網路擷取**(E1 規格已定離線唯讀,無 registry)。

**③ 注入介面**——`language` 仍不碰 `std::fs`,維持 §4 與 wasm 綠:
```rust
impl LibraryCatalog {
    pub fn embedded() -> …                                  // 隨附集合
    pub fn with_packages(extra: Vec<LibraryPackage>) -> …   // 新:host 注入
}
```
讀檔的是 host(`persistence`/未來 `app`)。wasm 前端無 fs,由 app shell 供給,走同一介面。

**④ 專案級 lock**:`packages.lock.json` 記錄解析結果(含遞移依賴)的 id/version/sha256。
digest 演算法沿用 `sha256_hex(package_lock_content(..))`,與 `.chg` 第三道 digest 同源,
兩者必須一致。

> **誌誤**:曾主張「內嵌保證跨機器 replay」。**錯**。lock digest 是執行期對 package
> 內容取 sha256,從磁碟讀入再雜湊得到**完全相同**的保證。內嵌對可重現性零貢獻。

### R3 附則 — 檔案格式依「功能與編輯方」

| 檔案 | 編輯方 | 功能 | 格式 |
|---|---|---|---|
| `packages/<n>/package.toml` | 人(套件作者) | 宣告 | **TOML**(取代自製 `.conf` 解析器) |
| `project.toml` | 人(專案作者) | 專案宣告 + import 表 | **TOML** |
| `packages.lock.json` | 機器 | 解析結果 + digest | **JSON** |
| `nodes/<id>/{manifest,edges}` | 機器 | immutable 快照 | JSON(現況不動) |
| `nodes/<id>/config`、`views/*.json` | app | 偏好 / 詮釋 | JSON(現況不動) |
| `exports.tsv`、`data/*.tsv` | 人 + 資料 | 表格 | **TSV 不變**(裁定只涉 `.conf`/`.lock`) |

實作前提:`serde`/`serde_json` 已是既有依賴,**`toml` 不是**——新增一個 crate
(純 Rust、無 fs、wasm 相容),仍屬《執行語意規格》§9-1「先查 crate」的範圍。

### R4 — Classification Override 一套一檔
`views/<name>.json`。切換視角 = 換檔,不同視角的編輯互不污染 diff。

### R5 — `cache/` 不落地
延到需要處理大專案時再議。目前 Compiled Grammar 可丟(P8)、lazy compile cache 留記憶體。

### R6 — bundle 延後
目錄形式對 git 友善(內容定址檔不可變、不衝突)。若日後要做單檔封裝,
`objects/` 是現成基礎。與 P65–P68 一併處理。

### R7′ — `std:*` 只是隨附的 package

> 如同 C++ 的 std:**隨編譯器發布,但只是一個 library**。它提供的是某種**語言學分析**,
> 不是引擎功能。引擎不得給它特權。

**實測支持**:引擎對 ontology 是不可知的。完全不給 std、只用自訂 trait 樹:

```
build 診斷 = []                          closure(MyNoun) = ["MyNoun","MyRoot"]
syn.categories = ["MyNoun","MyRoot"]     SemNode.types = []   gloss = Some("DOG")
check_language errors = []
```

沒有 std 時失去的是**共通詞彙**,不是執行能力。

> **誌誤**:曾主張「沒有 `std:core` 引擎會全盤崩」。**錯**,如上實測。`sem.rs` 每次使用
> std 名稱前都先 `reg.has(..)`,是刻意的軟依賴。該主張曾被我用來替「保留 prelude」辯護,
> 理由不成立。

**推論**:`LibraryCatalog::select()` 現行無條件把所有 enabled 的 `kind == Std`
package 當作 root。這是**目錄的政策,不是引擎的事實**,與 S 牴觸,應改由 import 表宣告
(切法見 R12)。

## 4. 由 S 揭露的既有缺陷:引擎碼裡的語言學

`crates/language/src/sem.rs` 硬寫了三條語言學推論,以字串字面值引用 `std:core` 的詞彙:

```rust
bridge("Nominal",    "Entity",   &mut types);
bridge("Predicate",  "Event",    &mut types);
bridge("Adposition", "Relation", &mut types);
```

同類尚有 `sem.rs:146/167`(`Semantic` 根)、`system.rs:2605`、`printer.rs:630`
(預設 slot 約束寫死 `Nominal`)。

### 4.1 實測:bridge 載重,但非必須

| 寫法 | `SemNode.types` |
|---|---|
| `belongs Noun`(靠 bridge) | `["Entity", "Semantic"]` |
| `belongs Noun` + `belongs Entity` | `["Entity", "Semantic"]` |
| `belongs Entity` | `["Entity", "Semantic"]` |

三者**完全相同**。原因在 `of_sign` 根本不看 bridge,只篩閉包裡誰是 `Semantic` 的後裔:

```rust
.filter(|c| reg.has("Semantic") && reg.category_is_a(c, "Semantic"))
```

`Entity belongs Semantic`,故只要閉包含 `Entity` 即入 `types`。
**bridge 唯一多做的是「自動推論」,沒有提供 `belongs` 做不到的能力。**

拿掉三行 bridge → **6 條紅**(全在 cxg/english 構式:fixture 只宣告 syn 範疇,
靠自動推論滿足 `referent [Entity]` 這類 role 約束)。故不可直接刪,須先補宣告。

### 4.2 bridge 的原始理由已不成立

程式碼註解稱 bridge 存在是為了「避免 `belongs Verb` 污染 syn 範疇閉包」。
但單一中立樹(P38 v0.2)下這件事**早就在發生**且被測試明確承認:

```
belongs Verb + belongs Transfer →
syn.categories = ["Verb","Predicate","Transfer","TransferFrame","EventFrame","SemanticFrame","Semantic"]
```

`tests/ontology.rs` 斷言此結果,註解寫「分類閉包**維度中立**」。
bridge 想迴避的東西根本沒被迴避。

### 4.3 裁定與落地(R11,**已完成**)

bridge 符合 S 的判準——**是語言學分析,不是功能**——且:
- 不提供 `belongs` 做不到的能力;
- 迴避的問題其實沒迴避到;
- `Adposition → Relation` 對格標記語言未必成立,是有爭議的主張。

**裁定**(擁有者 2026-08-04):搬進 `std:core` 寫成一般的 `belongs`,零新語法;
`Adposition → Relation` **拿掉**——格標記類介系詞未必表達 `Relation`,
應由作者顯式 `belongs Relation`。

```lang
trait Nominal:
    belongs AgreementBearer
    belongs Entity        /* 新 */
trait Verb:
    belongs Predicate
    belongs Event         /* 新;掛 Verb 而非 Predicate,故 Copula/Aux 不自動取得 */
```

落地後的連帶更動(皆為裁定的直接後果,非缺陷):

| 變化 | 說明 |
|---|---|
| 閉包變長 | `closure(Ditransitive)` 現含 `Event, EventFrame, SemanticFrame, Semantic`;`tests/ontology.rs`、`construction_german.rs` 的期望值隨之更新 |
| `Transfer ≠ Event` 不變式改觀察對象 | `give` 現在**是** Event,但經 `Transitive→Verb→Event` 而非經 `Transfer`。原不變式改在一個非 Verb 的 Transfer sign(`frame_only`)上觀察,否則被 Verb 那條路徑遮蔽 |
| `std:cxg` 的介系詞 fixture | `sign marker` 補 `belongs Relation` |
| golden `.chg` | `std:core` digest 隨套件內容變更(逐條理由見 commit) |

### 4.4 同一類越界:`Semantic` 過濾(R14,**已完成**)

移除三條 bridge 之後,`sem.rs` 仍有兩處硬寫 `std:core` 的 `"Semantic"`:

```rust
.filter(|c| reg.has("Semantic") && reg.category_is_a(c, "Semantic"))  // 過濾出「語意型別」
if reg.has("Semantic") { types.push("Semantic".to_owned()); }         // 無條件塞進每個 sign
```

第二行的用意寫在原註解裡:讓 `roles: [Semantic]` 能當作「任何有意義的節點」使用
——也就是 **role 缺少 `[*]`,用一個 std trait 名頂替**。

**掃描 15 處 `[Semantic]` 的意圖**,結論是無一真需要子樹成員檢查:

| 組 | 數量 | 情形 |
|---|---|---|
| A | 6 | slot 是 `[*]`,role 是唯一約束 → 意圖就是 `[*]` |
| B | 8 | slot 已約束(`[Noun]`/`[Nominal]`/`[Verb]`/`[CommonNoun]`),`[Semantic]` 恆真、加不了限制 |
| C | 1 | 負例 fixture,綁到不存在的 slot,約束無關 |

**裁定**(擁有者 2026-08-04):role 約束比照 slot typed 化並補 `[*]`;
15 處全部遷移;移除兩處 `Semantic` 硬寫;`types` 即完整閉包。
`SemanticDocumentV1` 的 `types` 出境內容照改,**承認它就是閉包**。

這同時解掉先前「`syn.categories` 看起來很怪」的觀察:單一中立樹下只有一組範疇,
而引擎一直在用 std 專屬的名字製造它的過濾副本。`RoleDecl.constraint` 複用既有的
`SlotConstraint`(不另造平行型別),`[*]` = `AnySign`。

## 6. 誌誤

本輪三次「沒查證就替現狀找理由」,一併記下以免重蹈:

| # | 錯誤主張 | 實情 |
|---|---|---|
| 1 | 「內嵌保證跨機器 replay」 | lock digest 是**執行期**對 package 內容取 sha256;從磁碟讀入再雜湊保證完全相同。內嵌對可重現性零貢獻 |
| 2 | 「沒有 `std:core` 引擎會全盤崩」 | 實測:完全不給 std,建構零診斷、閉包/投影/義項全正常、`check_language` 零錯誤。失去的只是共通詞彙 |
| 3 | 「role 約束的 `reg.has()` 是 fail-open 漏洞」 | `system.rs` 早有 `ROLE_UNKNOWN_CONSTRAINT` 編譯期把關;該 guard 是第二道防禦,未知約束到不了執行期 |

三次都是同一個毛病:**先替現狀構造理由,再去找證據**。正確順序相反。

沒有反例。補 `tests/role_constraints.rs`(含 `nouny` 通過 / `verby` 被擋的判別對)
