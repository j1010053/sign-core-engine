## 0. 修補摘要(一段話)

共時系統分成**四個內容彼此獨立的維度** phon/syn/sem/prag,**共享基礎設施**(Sign 身分
與引用、`Defs` 單一資訊源、parser/resolver/diagnostic、serialization),並依 P38 v0.2
共享**一棵維度中立分類樹**。每維仍各有 typed projection、validation、patch、diff。
**Morphology 不是第五維**,而是 Sign/construction/slot
與四維資訊互動的區域。`Defs` 恆為單一資訊源;`sign.phon()/syn()/sem()/prag()`
是對 `Defs` 的**型別化解讀**(不另存易失同步的副本);修改走 **typed patch**
(`Sign × Patch → Sign'`,保留原 Sign 不就地破壞)。分類統一用 **`belongs`**
(取代易混的 provide/provides)。**Valence = slots 結構**(非數字欄位)。
**Construction 也是 Sign**(帶 slots 的 Sign),填 slot 產生新 token/derived Sign,
**不就地改原 Sign**。條件分支用 **Lexurgy 式 `Else`**(Matched/Unmatched/Error
三分,`matched==0` 才進 Else,逐求值單元判定)。

## 1. 四維獨立 + 共享基礎設施【P38】

```
                 共享(單一資訊源 + 設施)
   Sign 身分/引用 · Defs · trait/ontology · parser/resolver/diag · serialization
                 │
                 ▼
       OntologyRegistry(單一維度中立分類樹)
                 │
   ┌─────────────┼─────────────┬─────────────┐
   ▼             ▼             ▼             ▼
 phon          syn           sem           prag        ← 四個獨立維度
 projection    projection    projection    projection
 validation    validation    validation    validation
 patch/diff    patch/diff    patch/diff    patch/diff
```

- **維度正交**:每維有自己的 typed projection、validation、patch、diff 與 rule write-set;
  ontology 分類樹只有一棵。
  syn 規則只改 syn projection,不得直接改 sem/phon(跨維效果由 construction 或
  更高層協調,§7/P44)。
- **Morphology = 互動區,非平行維**:Sign、construction、slot 與四維資訊互動之處;
  不設第五棵樹、不設 morph 專用 AST 維欄位。
- **共享 vs 不共享的界線**:共享的是分類、身分與**設施**(怎麼存、怎麼解析、怎麼報錯、
  怎麼序列化);不共享的是四維內容與直接寫入集合。

## 2. Defs 單一資訊源 + typed projection + typed patch【P39】

```
Defs  ── typed projections ─▶  PhonProjection / SynProjection / SemProjection / PragProjection
      ── typed patches     ◀─  PhonPatch / SynPatch / SemPatch / PragPatch
```

- **`Defs` 恆為唯一儲存層**(承 P21:IR 無隱藏狀態):`sign.phon()/syn()/sem()/prag()`
  只是對 `Defs` 的**型別化解讀**,不保存第二份易失同步的資料。
- **修改不暴露可變 projection**,而是 typed patch:概念上 `Sign × Patch → Sign'`,
  **保留原 Sign,不就地破壞**(承步驟 10–12 的純函數風格:每個 pass/apply 皆
  `X → X'`)。patch 分維(§7),各只改自己那維的 Defs 子集。
- **與 P28 對偶性相容**:typed patch 是 `update` 原語(P23)在四維上的型別化面貌;
  M2 的 ChangeSet 四原語(步驟 13)對四維 Defs 操作即透過對應 patch 類型。

## 3. `belongs`:統一分類 + 展開 + 標記機制【P40】

**取代** provide/provides(易混淆);統一採 `belongs TraitName`。一個 `belongs`
同時表示三件事:

1. **成員**:此 Sign/trait 屬於該具名 trait;
2. **展開**:編譯時展開該 trait 的模板內容(承 P5 macro 展開精神);
3. **保留標記**:展開後**保留 trait 名稱標記**,供分類與 slot 匹配使用
   (**與 P5 「展開即消去引用」不同**——`belongs` 展開後標記存續,是分類鍵)。

```
Give belongs Transitive          Give belongs {          slot 判定 filler:
Transitive belongs Verb    ⟹        Transitive             predicate [Transitive]
                                     Verb          }       ⟹ filler 的 belongs
                                                              閉包須含 Transitive
```

**belongs 閉包**(遞迴展開祖先鏈)須處理:

- **遞迴展開**(祖先鏈逐層);
- **重複引用去重**(多路徑到同一祖先只算一次);
- **循環偵測**(`A belongs B`、`B belongs A` → diagnostic,不得無限展開);
- **本地 Defs 與 trait Defs 的衝突**(承 P6 位置語意「後者勝」,本地覆蓋祖先;
  衝突須可診斷);
- **trait 來源追蹤 + diagnostics**(每個展開來的 Def 記得來自哪個 belongs 祖先,
  供 Find References 與衝突報告;屬 Compile Artifact,P8,不入語意)。

> **與 P5/P27 的關係(I19 已裁決)**:`Name[n]` 保留為 block-indexed macro 展開;
> `belongs` 負責單一分類樹、有效內容繼承與保留分類標記。兩者並存分工。

## 4. Valence = slots 結構(非數字欄位)【P41】

Valence **不設獨立數字欄位**;valence 就是 Sign 尚待滿足的 argument slots 所構成
的結構。三價 = 有三個必填 slot,**不寫** `valence: 3`。

```
Give:                          Sleep:
    belongs Verb                   belongs Verb
    Slots:                         Slots:
        agent     [Nominal]            experiencer [Nominal]
        theme     [Nominal]            location    [Locative] optional
        recipient [Nominal]
```

第一版 slot 至少需:**slot 名稱**、**filler 所需 trait/類型**、**是否 `optional`**。
slot **預設必填**,非強制才標 `optional`。不先加複雜 repetition、任意 cardinality、
完整 constraint language(承 07 §3.1「最弱夠用 + 逃生艙」)。

## 5. Construction 也是 Sign【P42】

Construction **不是獨立於 Sign 的特殊物件**,它本身就是**帶 slots + phon/syn/sem/prag
的 Sign**:

```
VO-Nominal:                    construction + slot fillers
    belongs Noun                 → validation
    Slots:                       → derived Sign/token
        predicate [Verb]         → phonological projection
        object    [Nominal]      → sound change
    Phon: {predicate} {object}
    Sem:  ...
```

填入 slots 後產生**新的 token / derived Sign**(承 07 §3.2:暫態 token,不進庫;
只有 entrenchment 跨閾值才固化——但固化行為屬 12e 之後,見 §8)。

**Construction 改變 valence = 產生新 Sign,非就地改**:recipient omission 不刪
原 `Give` 的 recipient slot,而是產生 `give(agent, theme)` 這個**另一個 Sign**。
所謂「減少 valence」實為 construction 重新暴露/映射/滿足輸入 Sign 的 slots,
產生新 Sign。需要的核心概念 = **slot mapping**:

- 保留輸入 slot;
- 將輸入 slot 對應到輸出 slot;
- construction 自己填入某 slot;
- 某語義角色仍存在,但不再作為對外待填 slot;
- 將 slot 改為 optional。

M1++ 以 typed `SlotMap`/`SlotMapOp` 提供 preserve、rename、autofill、internalize、
optional override；整份 mapping 先驗證再原子套用。2026-07-21 補齊 `.lang` 表面：
`syn:` 內使用平坦 `map SLOT preserve|internalize`、`map SLOT rename|autofill NAME`、
`map SLOT optional true|false`，與 Rust API 共用同一 AST 型別；不記 token attestation。

## 6. Lexurgy 式 `Else`:三分結果【P43】

`Else` 屬於**一個規則單元**(非一般程式語言先算獨立布林的 `if/else`)。語義:
嘗試前一分支,**若沒有合法匹配 → 執行 Else**。三種結果須區分:

| 結果 | 判定 | 行為 |
|---|---|---|
| **Matched** | 至少一個合法匹配 | 跳過 `Else` |
| **Unmatched** | 零匹配(`matched == 0`) | 執行 `Else` |
| **Error** | 型別錯誤、非法 path 等 | 直接 diagnostic,**不得偷偷進 Else** |

- **「匹配但值沒實際變化」仍算 Matched**——否則資料原本剛好等於目標值時會誤落
  Else(identity rewrite 阻擋後續 Else,對齊上游 tshiatun 協作規範 §2-4)。
- 內部可保留 `matched count` / `changed count`,但 **Else 判斷依據 = `matched == 0`**。
- **逐求值單元個別判定**(每個 Sign 或 construction token 各判一次),**非整批共用
  一個布林**(對齊上游「word stage FirstMatching 每 pword 分別選 branch」)。
- **關係**:精化 P22 的 else 鏈(P22 定「第一匹配勝出、單趟 disjunctive」;本 P43
  補足三分結果語義與逐單元判定,並澄清 identity=Matched)。

## 7. 四維同步規則:每維改自己那維【P44】

規則明確分維:`phon rule` / `syn rule` / `sem rule` / `prag rule`。每維規則**只直接
修改自己的 projection**,產生自己的 patch(PhonPatch/SynPatch/SemPatch/PragPatch)。
**跨維效果由 construction 或更高層協調**,不讓 syn rule 任意直接改 sem/phon。
條件分支用 §6 的 `Else`。規則執行須保留:

- **matched**(是否命中);
- **changed**(值是否實變);
- **diagnostics**(分級,承 B9);
- **source location**(行號定位);
- **deterministic order**(書寫序,承 P9/P26)。

> phon rule 已由 dsl 引擎承載(對 Word 求值);syn/sem/prag rule 對 Sign 的
> projection 求值(language 域,承 P20 §1.5 兩域劃分)。四維規則求值於步驟 12d 落地。

## 8. 路線圖:步驟 12a–12e(插入 M1 與 M2 之間)

**12e 界定(擁有者定案)**:12e **先只留介面與資料欄位**,**不實作 entrenchment/
lexicalization 行為**。先把共時四維系統做穩,再接歷時或使用頻率層。

| 步驟 | 內容 | 出口 |
|---|---|---|
| **12a** | **單一分類樹 + 四維 typed projection**:`belongs` 遞迴展開、菱形去重、循環偵測、較近祖先／同層後寫／本地優先序、來源與衝突 diagnostics。`Defs` 仍唯一儲存層 | `ValidationReport`;閉包、優先序、繼承 Def/slot/rule 反例 |
| **12b** | **Construction 與 slots**:construction-as-Sign;required/optional;部分套用;typed Rust `SlotMap` 五操作原子驗證;stored Sign 或 derived token filler | 德語變位 + SlotMap + 遞迴 token filler |
| **12c** | **Construction semantics**:derived token 同時攜 phon/syn/sem/prag、分類、殘餘 slots 與 provenance;遞迴 semantic node | 公共入口 form-meaning 端到端與決定性 |
| **12d** | **四維同步規則**:Sign/token 逐單元三分;Then feeding/Error 中止;真實 source line;phon Then/Else 直接排放 Tshiatūn | `.lang`/`.qy` differential + RuleRecord/source map |
| **12e** | **四維 patch 介面 + 資料欄位**:Patch 欄位私有、validated builder/parser、per-dim diff、last-wins Set/Unset;entrenchment/lexicalized 僅資料 | diff/apply、序列化、meta 欄位與一鍵閘門 |
