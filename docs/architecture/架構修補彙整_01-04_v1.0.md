## 2. 四份修補的核心內容(摘要)

### 修補 01:共時規則系統與臨時韻律域
**問題**:DSL 誕生於「詞表演化」世界觀(語言=詞表,演化=對詞表套規則),與 sign 本體矛盾;多式綜合語的組合無限,不可能枚舉。
**解**:語言 = sign 的 UR(有限)+ 共時規則系統(有限);表層按需導出、永不儲存;歷時 = 編輯這兩個有限儲存。`Word` 改職為臨時韻律域(七層 μ σ Ft ω φ ι U)。
**理論靠山**:生成歷史音韻學(規則增/刪/重排/倒置、restructuring);音韻過程生命週期(Bermúdez-Otero);Stratal OT;Cophonology Theory(構式語法家族)。
**關鍵紅利**:表徵、規則語言、單規則執行語意**完全不變**——只動組織層,M0 引擎核心一行不改。

### 修補 02:Trait 機制
**問題**:raising verb / animacy / 語義組——大量內容本該寫進多個 sign 但相同。
**解**:Trait = sign 內容的可共享 macro 展開模板(非新本體);`==` 分 block,`<名>[n]` 顯式引用,全 block 強制寫入;Global = 預設自動引用的最低優先 trait,無特殊本體。
**統一**:受控本體範疇 / schema / 全域約束 三機制合一為 trait 的三種用法。

### 修補 03:Trait 與 Compiled Grammar
**問題**:Grammar 不該等於執行資料;Rule Order 與 Priority 被混為一談。
**解**:**Grammar Source(→更名 Language)**= 語言知識;**Compiled Grammar** = 編譯產物、引擎執行表示。Definition(`=`)/ Rule(`=>`)二分。Priority 僅管 compile 合併,compile 後消失。

### 修補 04:共時/歷時分離與歷時實作分層
**問題**:共時與歷時的責任未分;歷時操作缺乏分層。
**解**:共時宣告式(靜態編譯器)/ 歷時命令式(直譯器改寫 Language);歷時四層(Primitive Edit / Atomic Rewrite / Recipe / Goal);Goal 與 Recipe 解耦;新增 State 佔位。
**產品意義**:層級介入取代自動/手動二分——使用者在任一層停止自動化。

## 3. 裁決彙整(A/B/C → P14–P19)

### 3.1 A3 檢核結果:Atomic Rewrite 定案 12 項(P16)

**判準**(CLAUDE.md §6):單步 + 正交 + 有穩定慣例名 → Atomic Rewrite;否則降 Recipe 或參數化特例。

```
form:   sound_change(rule)                         → 委派 DSL 編譯器
sem:    drift{direction?}                          → 量化交 SemanticBackend
        derive_sense{kind: metaphor|metonymy|narrow|broaden}
        lexicalize_sense                            → 衍生邊 → opaque
syn:    reanalyze{target: Valence|Category|Slot|Boundary}
usage:  entrench{delta} / attrit{delta}
        lexicalize                                  → token→type(僅此義)
結構:   create(target) / delete(target)
        split(target) / merge(a,b) / fuse(a,b)
接觸:   adopt{source: Loan|Dialect|Ancestor}
居所:   fossilize(rule, →下一級) / generalize(rule, →上一級)   ← Life Cycle 軸(P14)
```

**修補04 清單的修正**:

| 修補04 項 | 裁決 | 理由 |
|---|---|---|
| `bleach` | → `drift{direction: bleaching}` | 非正交:有方向的 drift |
| `shift_category` | → `reanalyze{target: Category}` | 非正交:reanalyze 的特例 |
| `semantic_extension` | → `derive_sense{kind: broaden}` | 非正交 |
| `semantic_narrowing` | → `derive_sense{kind: narrow}` | 非正交 |
| `morphologize` | → `fossilize(rule, → construction trait)` | 非正交:居所下移的特例 |
| `cliticize` | → **降 Recipe** | 非單步:reanalyze{Boundary} + entrench + sound_change(磨損) |
| `specialize` | → **刪除** | 重疊:若指居所下移=`fossilize`;若指條件變窄=`set(rule.condition)`(Primitive Edit) |
| *(漏列)* | **補回**:`sound_change`/`drift`/`derive_sense`/`adopt`/`entrench`/`attrit`/`lexicalize_sense` | 修補04 漏了 docs/08 已定的 6 項(含最基本的音變與借詞) |

**三個 lexicalize 的消歧**(檢核中浮現的命名陷阱):
1. **usage-based `lexicalize`**:token 跨 entrenchment 閾值 → type。**`lexicalize` 專指此義**。
2. **音韻 lexicalization**(表層烤進 UR + 規則死亡)→ 實為 `fossilize(rule, → sign UR)`,**非獨立操作**;修補01 的 `Lexicalization` 宏改名為 Recipe **`PhonologicalLexicalization`**。
3. **修補02 的 Fossilize**(規則 trait→sign)→ 與 2 同一個。

**`fuse` vs `merge` 不重疊**:`fuse` = A+B→C(線性組合,au=à+le);`merge` = A,B→A(範疇塌縮,syncretism)。

### 3.2 三層 → 四層的映射(P11/P15)

| 原(docs/08) | 新(P11) | 說明 |
|---|---|---|
| — | **Primitive Edit** | 新的最底層:純 AST 操作(insert/delete/replace/rename/move/set/unset),**無語言學知識** |
| L1 純資料原語 | **拆解** | 純 AST 部分(Modify/Reference/SetTransparency)→ 降為 Primitive Edit 的參數;帶本體部分(Create/Delete/Split/Merge)→ 升為 Atomic Rewrite |
