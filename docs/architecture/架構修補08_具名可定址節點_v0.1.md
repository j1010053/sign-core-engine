# 架構修補08 — 具名可定址節點（P45）

> **決策來源**：本檔提出並定稿 **P45**；現行權威為《架構修補彙整 05–11》§1。
> 承 P24（引用是 Ref 屬性值，四原語樹上封閉）、
> P25（穩定 ID 為定址權威）、P26（決定性 id）。owner 於 2026-07-24 裁定「取徑 B：直接標籤」，
> 不採「sign 內具名 `==` 區塊」。

## 背景與問題

`.chg` 授權層以 authoring path 定址無名節點（`rule[n]`／`else[m]`／`then[m]`／`realization[k]`／
`case[n]`／`branch[m]`），序數對重排敏感。Lexurgy 以「具名 rule／stage」定位；`.lang` 原無等價。
需要**人類可讀且穩定**的定址鍵，讓授權端不必依賴序數。

## 已否決取徑：sign 內具名 `==` 區塊

`SignDef { items: Vec<SignItem> }` **刻意扁平**——parser 解析 sign 時把 `==` 切出的 block
**當場展平**（`blocks.into_iter().flat_map(|b| b.items)`），只有 `TraitDef` 保留 blocks（供
`Name[n]` macro 索引，P5/P27）。在 sign 內保留具名 block 需逆轉此扁平設計、改動遍布 compile／
codegen／construction／synchronic／identity 位址模型／printer／四原語的 `sign.items` reader，
blast radius 過大，且 block 於 compile 仍會展平（無語意效果）。**否決。**

## P45 決策：節點直接具名標籤

**§1 資料**：`Rule`、`TypedCase`、`CaseBranch` 各新增 `name: Option<String>`（`None` = 匿名）。
標籤是**授權層便利定址鍵**，非語意載體；compile/codegen 不讀它。

**§2 語法**：後綴 `@name <label>`（`<label>` 為單一識別字）。
- Rule：`<body> @name <label> @stage <stage>`（`@name` 在 `@stage` 之內）。
- Case header：`case <scrutinee> @name <label>:`／`when … @name <label>:`（`@name` 在 `:` 之前）。
- Case branch：`== VALUE @name <label>:`／`else @name <label>:`／`<guard> @name <label>:`。

printer 僅於 `Some` 時輸出 → 未具名節點的 canonical dump **逐位元不變**（無 golden churn）。

**§3 定址**：keyed path 段——`rule["label"]`／`case["label"]`／`branch["label"]`。
規約：`["…"]`（引號）或**非數字** argument ＝ 按標籤；純數字 ＝ 序數（既有）。與既有
`def[path]`／`slot[name]`／`role[name]` 的 keyed 定址一致。

**§4 canonical／round-trip**：標籤**不取代** P25 的穩定 id。resolve 後所有 selector（含 keyed）
一律釘成 `node(<kind>, @ns:ord)`；dump 只輸出穩定 id。標籤純為 source 授權端可讀性，replay
決定性仍靠 P25/P26 的 id（P45 不改此不變式）。

## 相容性

- **P24**（四原語樹上封閉）：標籤是節點欄位值，非圖邊/引用；不新增跨樹邊。相容。
- **P25**（穩定 id 定址）：標籤是**附加**的授權層鍵，權威定址仍是穩定 id（§4）。相容、不取代。
- **P26**（決定性 id）：標籤不參與 id 配發；replay 逐位元可重現不變。相容。
- **sign 扁平（既定）**：不動 `SignDef.items`；標籤住 Rule/Case/CaseBranch 欄位。相容。

## 範圍與邊界

- 本決策只加「可選標籤 + keyed 定址」。**不含**唯一性強制（同名多節點時 keyed 取第一個命中；
  未來若需可加 duplicate-label 診斷）。
- **不含** Slot/Def/Role 的標籤（那些本就 keyed by name）。
- ~~**不含** realization branch 標籤（`RealizationBranch.guard` 已可辨識；未來如需再議）。~~

> ### ⚠ 更正（2026-08-17）：上一條的理由與結論都已不成立
>
> **理由已失效**：`RealizationBranch` 這個型別在 V1 路徑移除時就一併刪掉了。
> `Realization` 現在是 `{ expression: Option<TypedCase> }`（`language/src/lib.rs:439`），
> 分支即 `CaseBranch`，而 `CaseBranch.name` 正是本決策 §1 加的欄位。
> 所以「realization branch 沒有標籤欄位」在今天是錯的。
>
> **實測結果**（`realization:` 內寫 `case @name X:` 與 `<guard> @name Y:`）：
>
> | 面向 | 結果 |
> |---|---|
> | parse | ✅ 接受 |
> | canonical dump | ✅ 標籤原樣印出、round-trip 穩定 |
> | `.chg` keyed 定址 | ❌ **全部解不到** |
>
> 六條路徑實測皆失敗：`sign("x").case["X"]`、`…case["X"].branch["Y"]`、
> `…case[0]`、`…branch["Y"]` 都回 `cannot resolve … below <sign>`；
> `sign("x").realization[0]` 回 **`unknown path selector "realization"`**。
>
> 原因是位址樹的形狀，不是標籤缺失：`SignItem::Realization` 自己是一個
> `NodeKind::Realization` 節點，其下才掛 `NodeKind::Case`（`identity.rs:1089`）。
> 而 `resolve_path_child` 的 `children` 只取**直屬子節點**
> （`changeset/src/lib.rs:3089`），且**沒有 `"realization"` 這一支**可供下降。
> 對照組 `sign body` 直屬的 `case:` 因為本身就是 sign 的直屬子節點，
> `case["X"]` 可解（`named_addressing.rs` 已證）。
>
> **淨效果是最壞的組合**：標籤寫得進去、印得出來、看起來成立，但沒有任何
> selector 到得了它——作者收不到任何訊號。這與本檔開頭「序數對重排敏感、
> 需要人類可讀且穩定的定址鍵」的動機正好在 realization 上落空。
>
> ### 修法：取徑 A（讓 `Realization` 塌陷），不是補選擇器
>
> 曾考慮兩案。**裁定取 A。**
>
> | | 做法 | 評估 |
> |---|---|---|
> | ~~B~~ | 補一支 `"realization"` path selector，`realization[0].case["X"]` 兩段下降 | **否決** |
> | **A** | `item_kind(Realization)` 改回 `expression_root_kind`，case 直接掛在 item 位址上（少一段 `CaseExpression`） | **採用** |
>
> 否決 B 的三個理由，全部是維護面的：
>
> 1. **B 不是通往 A 的中繼站，是岔路。** B 一旦可用，作者就會在版控的 `.chg` 裡寫下
>    `realization[0].case["X"]`；日後若做 A，那一段消失，所有寫過的路徑都要遷移。
>    B 每多用一天，A 就更貴。
> 2. **B 把序數塞回 keyed path 的正中間。** 本檔「背景與問題」的第一句就是
>    「序數對重排敏感」——用一個序數段去接通一條專為消滅序數而造的鏈，
>    正是本決策自己記載的失效模式。
> 3. **B 讓不對稱永久化。** `realization` 會是唯一一個 case 為孫節點的 item，
>    往後每個「找出這個 sign 的 case」的走訪都得記得它。
>
> A 的一次性代價經實測遠小於初判：全 repo 只有 3 個 `.chg`，兩個套件內的
> （P49 definition-file mode）`node(` 出現 **0 次**；`tutorials/en-standard-reconstruction/restore.chg`
> 的 85 個 `node(...)` **全部是同一個 id** `@evo:en-standard:0`（language 根，
> base 為空文件），sign 內部位址一個都沒被引用；快照檔無一釘節點 id 或提及 realization。
> **沒有任何持久化位址會壞。** 成本在程式碼面：`NodeKind::Realization` 約 24 個引用點，
> 外加 `NodeUpdate::Realization`（`changeset/src/lib.rs`）要改走既有 Case 更新路徑。
> 但那 24 點在 B 之下是**永久保留的特例**——A 是付一次，B 是一直背。
>
> 先例對得上：`fp_v2.rs` 記載舊 `schema conlang.lang/v2` 標頭選擇**拒絕而非忽略**，
> 理由是「無意義的輸入靜默通過，會讓作者以為那行有作用；本專案未曾發布，
> 沒有既有檔案需要相容」。`realization:` 裡的 `@name` 是同一形狀的東西。
>

>   該不變式現由型別保證。workspace 115 個測試 binary 全綠。
