# Tier 音變 DSL — 執行語意規格(v0.1)

配套《語法規格 v0.3》。語法規定「能寫什麼」,本規格規定「怎麼跑」。核心決策來自執行語意決策清單 A/B/C 組與兩輪外部審查的採納結論。設計主軸:**單一 Execution Model 定義規則生命週期,各動詞只宣告自己採哪種語意,所有底層行為引用本章、不散落。**

## 1. Execution Model(規則生命週期)

所有規則——tier 內、韻律、Scan 塊內——共用同一條生命週期。這是本規格的權威來源,其餘各節只引用它。

```
Rule
  │
  ├─ 1. Parallel Match      以規則套用「前」的凍結表徵,一次找出所有匹配位置
  │                          (parallel 動詞在此階段一次定案所有位置)
  ├─ 2. Action Evaluation   對每個匹配位置計算其動作結果(尚未寫入)
  │                          iterative 動詞在此展開連鎖(見 §2)
  ├─ 3. Commit              將所有動作一次寫入表徵,產生新狀態
  ├─ 4. Validation          於此新狀態檢查良構:NCC(§4)、其他約束;產生警告
  └─ 5. Lazy Reparse Mark   若本規則為 query 類且韻律結構為 stale,在此觸發重剖(§3)
                             repair 類動詞跳過此步
```

- **序列點(sequence point)**:每個 Commit 是一個序列點。複合規則 `Then:` 的每一段各自跑完 1–5 才進下一段;同一規則名下的平行子項(如 tonogenesis 的 insert H / insert L)共享同一次 Parallel Match(步驟 1),故彼此不互相影響(B5)。
- **凍結語意**:步驟 1 的「前狀態」在整條規則內凍結,直到 Commit;這保證 parallel 動詞不自我餵食。
- 一條規則對某詞完全無匹配 → 靜默略過(info 級記錄)。

## 2. 動詞語意宣告表

A1 的框架只定義 parallel 與 iterative 兩種**執行語意**;每個動詞宣告採哪種。新增動詞(copy / drift / lower…)只需在此表加一列,不動 §1、不動 A1。

| 動詞 | 語意 | 說明 |
|---|---|---|
| `associate` | parallel | 所有加邊以前狀態判斷,一次 commit |
| `delink` | parallel | 同上,減邊 |
| `insert` | parallel | 造自體段 |
| `delete` | parallel | 刪自體段 |
| `fill` | parallel | 每個 Ø 各建獨立自體段(D22),一次 commit |
| `dock` | parallel | 一次媒合所有浮游者;多者同拍選中同一空錨點 → **全部接上**(多承載合法,D27)+ info;不裁決、不排隊 |
| `spread` | **iterative** | 連鎖擴散;方向強制顯式(D10);於步驟 2 逐格展開至遇界/blocker |
| `shift` | **iterative** | 逐格平移;方向強制顯式 |
| `merge` | parallel | OCP 合併,以前狀態一次判斷 |
| `dominate` | parallel(repair) | 結構修復;**不觸發 reparse**(§3) |
| `release` | parallel(repair) | 同上 |
| `parse` / `reparse` | — | 直接產生結構,自身即重剖 |

**Strategy 模組(D28)**:所有動詞的候選挑選(nearest、tie-break、自定義)統一由單一 strategy 解析器模組處理——輸入(候選集、方向偏好、tie-break 設定),輸出(零或一個選擇)。動詞不得各自實作挑選邏輯;自定義 strategy 以名稱註冊進同一模組,文法引用見《語法規格》§4。此為 §9 原則 2(基礎先行)與原則 3(單一資訊源)在挑選邏輯上的落實。

**iterative 展開語意**:iterative 動詞在步驟 2 內部逐格套用,每格以「該動詞在本規則內累積的中間狀態」判斷下一格——但這個中間狀態**不外洩**到規則外,步驟 3 才整體 commit。方向由動詞自己的 `leftward/rightward/bidirectional` 決定,不使用任何 evaluation 預設方向(A2)。

## 2.5 層疊套用(cyclic application;《架構修補01》P3)

單規則生命週期(§1)**零修改**;本節定義規則**批次的組織**——由 component 組合樹驅動:

1. **stem-level(循環)**:最內層詞幹先跑 stem-level 規則;每加一環(構式組合)再跑一輪,含該構式的 cophonology(若有;P4:僅使用者手動或 `Morphologization` 宏可建)。
2. **word-level(ω)**:整詞組合完成後跑一次。
3. **phrase-level(φ/ι/U = surface sandhi)**:spell-out 時跑(§6);每次導出、永不回寫。

每一輪內的每條規則仍走 §1 的五步生命週期;`stage` 標記(語法規格 §5;I14)決定規則屬哪一輪。M0 內所有範例(8.1–8.6)皆詞內,預設 `word` 即可;循環套用的實作留 sign 引擎階段(組合樹是循環的驅動者)。

## 3. Lazy Reparse

- `reparse: lazy` 為預設。音段變動後,韻律結構標記為 **stale**。
- **query 類動詞**(任何唯讀查詢韻律結構者:讀 `<syl>`、`<mora>&[+heavy]`、序數等)在其生命週期步驟 5 觸發即時重剖到最新,才執行查詢。
- **repair 類動詞**(dominate / release,§2 標 repair)**不**觸發 implicit reparse——判準在**動詞類型**,非其 selector 讀了什麼(A3 採審查修正)。故 repair 動詞永遠看到 **stale** 結構,這正是補償性延長的空莫拉能存活至被 `dominate` 修復的原因。
- 顯式 `reparse <level>` 隨時強制更新,不受上述限制。
- 使用者須知的一條反直覺事實(寫入文件顯著處):**修復動詞看到的是修復前的舊結構。**

## 4. NCC 與警告生命週期

- **檢查點**:每條規則的步驟 4(規則邊界),非每次 associate 後(A4)。故規則內暫態交叉不誤報。
- **違反行為**:依全域 `strict-ncc`(off / warn / error,預設 warn)。warn 時照建交叉邊、續跑。
- **生命週期**:警告一旦產生**不收回**;若後續規則解除了該交叉,將原警告標記為 `resolved-later`(保留除錯痕跡,但追蹤視圖可淡化)。
- **快照對齊**:每條規則一個 commit = 一個天然快照點,與未來 IDE 的逐規則視覺化對齊。

## 5. Locality(局部可達上界)

**定義(B7 最終,經使用者校正)**:一條 tier 內規則從當前錨點出發能唯讀觸及的範圍 =

> 沿**連結(association)+ 支配(domination)**關係的**可達閉包**,取以下兩者的**聯集**:
> (a) 當前錨點所屬的 `locality` 韻律成分**之內**(預設 `locality syllable`);
> (b) 沿**該旋律層自己的錨定層**,前後各**相鄰一格**。

要點:

- 它衡量的是「沿關係能否觸及」與「成分/相鄰邊界」,**不是路徑長度、不是跨界計數**。審查者「六莫拉同音節」的反例在此無殺傷力:六莫拉同屬一音節成分,經 σ 支配節點互相可達,全部可見——本就該如此。
- 「相鄰一格」在**該旋律層的錨定層**上數(tone 錨莫拉 → 相鄰莫拉;nasal 錨音段 → 相鄰音段),不一律用音節;與 Scan 的「along 哪條軌道用哪條刻度」同原則。
- (a)(b) 取**聯集**:成分內與相鄰一格哪個寬用哪個,不擋任何常見局部規則。
- **邊界即分工**:locality 上界 = tier 內規則的極限;超出者一律走 `spread`(的 within)或 `Scan`。locality 邊界與「誰該用 Scan」的邊界重合——這是本上界存在的唯一理由(落實「沿 link 只能搜當下所指」,把遠距關進 Scan)。
- `locality` 為全域參數,可設 `syllable`(預設)/ `foot` / `pword`。

## 6. Spell-out(純函數)

**C11 最終**:Spell-out 是一個**純函數** `Representation → Surface`。

- **禁止**:rewrite(帶環境的改寫)、search、spread、Scan、任何產生 `Representation'` 的操作。
- **僅允許**:lookup(查表對應)、flatten(壓平)、render(產生表層符號)。
- **phrase-level 規則在此執行(《架構修補01》P3)**:spell-out 接受 Grammar Store 的 phrase-level 規則組為**唯讀輸入**,對臨時韻律域(φ/ι/U)導出 surface sandhi;導出結果永不回寫表徵,純函數約束不變。M0 步驟 6 僅留掛鉤(傳空集)。
- 後果:真正需要環境的表層音變(如 Bantu downstep)**不可**寫在 Spell-out,必須是拼讀**前**的最後一條普通 tier 規則。
- 收益:純函數保證可快取、可平行、可最佳化;spell-out 永遠不會長成第二個規則系統。

宣告區塊(C10):

```
Spell-out:
    order      tone, nasal, atr        # 多層落同一音段的實現次序/優先(必需)
    empty      tone => M               # 殘餘 Ø 表層落值(查表,非規則)
    empty      nasal => bare           # 私有特徵殘餘 Ø = 不帶
    floating   tone => drop warn       # 殘餘浮游:drop | dock-to-edge | keep-mark | error
    contour    μ:{H L} => falling      # 多承載線性化(圖→串造符,必需)
    project    <syl> => stress-mark    # 韻律結構是否在表層留記號
    romanize-with  <romanizer-name>    # 拼讀後接的 romanizer
```

`order` 與 `contour` 為必需:前者定義多對一壓平的優先,後者是唯一創造新表層符號之處。**衝突檢查(D27)**:spell-out 對每個多承載錨點查 `contour` 對應——同層多值(含 dock 共同著陸產生者)若無對應項,報 **error**;有對應即正常線性化。衝突偵測因此集中於唯一整合點,推導期間不打斷。所有右端都是**表層符號或處置動作**,無環境、無改寫——這是純函數約束的語法體現。

## 7. 訊息分級(B9)

| 級 | 行為 | 範例 |
|---|---|---|
| error | 停止該詞演化 | `strict-ncc: error` 的 NCC;`on-unrealized-*: error`;強依賴的型態括號缺失 |
| warn | 記錄續跑 | 預設 NCC 違反;殘餘浮游 drop;`within stem` 因缺括號跳過 |
| info | 追蹤視圖顯示 | 動詞無目標 noop;lazy 重剖觸發;暫態交叉 resolved-later |
| trace | 逐步除錯模式 | 每個 commit 的前後狀態、iterative 每格展開 |

## 8. 開放項(不擋 M0)

- iterative 動詞的 `bidirectional` 展開,兩側是否嚴格交替逐格,或各自跑完再合(影響同拍衝突偵測的精確時機);
- `project <syl> => stress-mark` 對中間 romanizer 快照的一致性;
- trace 級輸出的資料結構(供演化樹視圖回放),與架構書 M2 對接。
-(原「parallel dock 競爭」項已由 D27 定案:共同著陸 + spell-out 衝突檢查,不再開放。)

## 9. 實作原則(M0 起全程適用)

1. **不重複造輪子**:動工前先盤點可直接套用的開源模組。M0 候選(Rust):`logos`(lexer)、`chumsky` 或 `pest`(parser)、`petgraph`(聯結圖/支配圖)、`serde`(專案檔序列化)、`insta`(快照測試——與 §4 的「每規則一快照」天然對齊)、`unicode-segmentation` / `icu4x`(IPA 與字位處理);FST 後端評估 `rustfst` 前先評估 ASCA 可否直接作地基(架構書 §8)。採用前逐一驗證授權與維護狀態。
2. **基礎先行,其餘由基礎實現**:先實作最小原語集,具名動詞一律以原語組合實現、不得另闢狀態——旋律層:`associate` / `delink` / `insert` / `delete` 為原語,`spread` = 迭代 associate、`dock` = 條件 associate、`shift` = delink+associate、`fill` = 逐 Ø insert+associate、`merge` = delete+associate;韻律層:`dominate` / `release` 為原語,parse 為批次 dominate。此與《語法規格》§3.3「原語兩個,其餘為具名特例」一一對應——語法上的特例關係就是實作上的組合關係。
3. **單一資訊源**:每個 identity(自體段、錨點、邊、警告、決策編號)恰有一個權威存放處,其餘皆引用——聯結邊只存在聯結圖中(自體段不自帶「我掛在哪」的副本)、序列位置只存在旋律層序列中、韻律結構只存在支配圖中、stale 旗標只存在結構層。文件層同理:每個概念恰在一份文件定義(spell-out → 本規格 §6;locality → 本規格 §5;selector → 語法規格 §3),其餘位置一律指向連結。
4. **功能完整下精簡**:以測試(範例集 8.1–8.6)界定「完整」,在其上追求最小可維護實作;優先刪抽象層而非加。原語集(原則 2)本身就是此原則的體現——引擎核心只需正確實作六個原語 + 生命週期(§1),其餘皆組合。
