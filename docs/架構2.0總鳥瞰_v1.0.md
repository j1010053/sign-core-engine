# 架構 2.0 總鳥瞰(v1.0)

> **性質**:2.0 架構的單一入口文件。詳細決策見《架構修補彙整 01–04》§1(P 系列權威表)。
> **1.0 → 2.0 的一句話**:語言不再是「詞表 + 規則腳本」,而是 **共時的 Language(靜態編譯)+ 歷時的 ChangeSet(直譯改寫 Language)**;表層永不儲存、按需導出。

### 三條鐵律

1. **Compile 僅存在於共時側**。歷時**永遠操作 Language**,不得直接碰 Compiled Grammar/Sign(P10)。
2. **語言知識只住 Language**(Global/Trait/Sign)。Compiled Grammar 是編譯產物,可丟棄重算(P8)。
3. **表層永不儲存**。歷時編輯有限儲存(Language),永不枚舉無限的組合空間(P1/P2)。

### 兩個軸不可混淆(P14)

| 軸 | 性質 | 操作 | 生命期 |
|---|---|---|---|
| **居所階梯** Global → Trait → Sign | 歷時、跨 compile | `fossilize`(下移)/ `generalize`(上移) | 永久(語言知識) |
| **Priority** global < trait < sign | 共時、compile 時 | 同欄位衝突解析(欄位粒度) | **compile 後消失** |

兩者同構(越具體越優先)但**不是同一個東西**。

## 2. 資訊傳輸流(四條)

### 流 A:共時導出(即時,毫秒)—— 「這個詞現在唸什麼」
```
Language ──Compile──▶ Compiled Grammar + Compiled Sign
                          │
        component 組合樹 ──┴──▶ 臨時 Word 建構
                                  ├─ stem-level 循環(逐環 + cophonology)
                                  ├─ word-level(ω)
                                  └─ spell-out:phrase-level(surface sandhi)
                                          ▼
                                       Surface
```
**快取**:Compiled Grammar 是純函數產物,可丟棄重算;臨時 Word 用完即棄。

### 流 B:歷時演化(批次,秒–分)—— 「這個語言怎麼變」
```
[使用者在任一層介入 ← 層級介入 P17]
Goal(函數)──▶ Vec<Recipe 候選>
                  │ ◄── Weight DB(E)+ seeded 抽樣器
Recipe(函數)──▶ Vec<AtomicRewrite>
                  │
AtomicRewrite ──▶ Vec<PrimitiveEdit>
                  │
PrimitiveEdit ──▶ Language′
                  │
              重新 Compile ──▶ Compiled Grammar′ ──▶ Engine ──▶ Surface′
```
**Replay**:`Evolution_node` 的 ChangeSet 序列展開 → 產物是 **Language**(不是 Compiled Grammar);每節點各自 compile。memoize 快取 Language。

### 流 C:生成(造詞)
```
Need ──▶ Generator(唯讀 Language + E 抽樣)──▶ Vec<Proposal>(帶評分)
                                                    │
                              [使用者挑選 / 自動採納]│
                                                    ▼
                          Builder(唯一寫入點)──▶ Language′
                            │ 委派 Strategy:validate / blocking / resolve
```

### 流 D:查詢(UI)
```
UI(唯讀引擎資料)
  │ Command API ──▶ 觸發流 A/B/C
  └ Query API ◄── 投影計算(辭典 / 語意場 / diff / 互通度 / 統計)
                    │ 參數:View Config + Classification Override
                    ▼
                  視圖(UI 只渲染)
```
UI 自己的狀態:Session State(ephemeral)/ View Config / Classification Override(政治-社會判斷,存專案設定檔,不回寫 Language)。

## 3. Debug 獨立模塊

**核心洞見**:歷時四層中,**上三層只做「展開」不做「執行」**——所以可以**只驗展開結果、不執行**(純函數 golden test)。真正「執行」的只有最底層(Primitive Edit 對 Language)與 Grammar Engine(對 Word)。

### 3.1 完全可獨立 debug(有明確 IR 邊界)

| 模塊 | 契約(輸入 → 輸出) | 隔離方式 |
|---|---|---|
| **Parser** | text → AST | golden:source → 期望 AST |
| **Compile 各 pass** | AST → AST | 每 pass dump IR;**Trait 展開可單獨驗**(展開前後 AST 對照) |
| **Grammar Engine** | Compiled Grammar + UR → Surface | **手寫 Compiled Grammar 繞過 compiler**;8.1–8.6 即此 |
| **Primitives**(associate/delink…) | Word → Action | M0 步驟 2 已在做 |
| **Primitive Edit** | Language → Language′ | 每個 op 獨立單元測試 |
| **Atomic Rewrite** | (rewrite, Language) → **Vec\<PrimitiveEdit\>** | **只驗展開序列,不執行** |
| **Recipe** | (params, Language) → **Vec\<AtomicRewrite\>** | 只驗展開序列 |
| **Goal** | (target, Language, State) → **Vec\<Recipe 候選\>** | 只驗候選清單(不含權重) |
| **抽樣器(E)** | (候選, 權重, seed) → 選擇 | 注入假權重表 + 固定 seed |
| **Generator** | Need + Language → Vec\<Proposal\> | 唯讀,天然隔離 |
| **Builder** | Proposal → Language′ | 唯一寫入點,契約清楚 |
| **Strategy 模組** | 候選 → 決定 | 可插拔,各自測 |

**四層各自的紅綠燈**:Goal 錯 → 候選清單不對;Recipe 錯 → rewrite 序列不對;Rewrite 錯 → edit 序列不對;Primitive 錯 → Language′ 不對。**錯誤精確定位到層,不必端到端猜。**

### 3.2 需注入 fixture 才能隔離

| 模塊 | 依賴 | fixture |
|---|---|---|
| Atomic Rewrite | 展開依賴 Language 當前狀態 | 固定 Language fixture |
| Goal | 候選依賴 State | 固定 State fixture |
| **SemanticBackend**(drift 量化) | 外部/LLM | **必須可 stub**——否則 drift 測試不確定(must-have) |
| 抽樣 | 隨機 | 注入 seed(既有規範) |

### 3.3 真正的整合點(無法單獨 debug)

1. **循環套用**:component 組合樹 × Compiled Grammar × 臨時 Word 三者交會。
2. **Replay**:Evolution_node 樹 × ChangeSet 直譯器 × Compile 鏈。
3. **Sign 引擎 ↔ DSL 引擎焊接**(phon 維 = Word)。
4. **Compile 的 Priority Resolution**(依賴 Trait 展開結果,同 pass 鏈內)——但仍可 dump 中間態定位。

### 3.4 三個必備基礎設施

1. **每層 IR 可序列化(dump)**——沒有這個,「分開 debug」只是理論。**這是規劃 primitive 時就要定死的東西**。
2. **每層可注入 fixture**(假 Language / 假 State / 假權重 / stub backend)。
3. **全域 seeded 決定性**(已在規範內)。

> **架構紅利**:共時=編譯器、歷時=直譯器——這兩種東西的 debug 手法在業界極成熟:編譯器用「每 pass dump IR」,直譯器用「每步 trace + 前後狀態 diff」。2.0 定位白撿兩套現成方法論。

## 4. 新的實作順序(M0 步驟 7 → M4)

**順序原則不變**:每步以「哪個測試綠燈」為出口,不做無測試出口的階段。

### 依賴鏈檢查

- **M1 必須先於 M2**:歷時改寫 Language,沒有 Language 就無從改寫(P10)。
- **步驟 13 必須先於 15**:下層先(Primitive Edit → Atomic Rewrite)。
- **步驟 15 → 17**:Atomic Rewrite → Recipe → Goal,逐層向上。
- **步驟 12(循環套用)需 component 樹**:M1 的 Language 已含 Sign.slots,可手寫組合 sign 測試;真正的**組合造詞**在步驟 18。
- **M2 / M3 可互換**:歷時只需 Language + Primitive Edit(增量小、核心賣點);造詞需 E1 先驗庫(資料整理工作量大)。建議 M2 先。
