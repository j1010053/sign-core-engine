# 分層結構檔本體論(v0.1.1)— 模組 C

一個語言節點(D 的一個 node)的內部結構。核心結論:**「七層」不是七個容器,底層只有 sign(form-meaning pairing);層是 sign 上的維度或視圖投影。** 本檔統一生成語言學(組合運算)與構式語法學(整體儲存),並標注實現梯次。

> **梯次圖例**:【M】MVP 已定 /【M+】MVP 後 /【N】v-next 留白 /【A/B驅動】待造詞(A)、語法化(B)模組的案例明朗後細化。
> D(演化圖)的差異向量(§6)依賴本檔;本檔的 phon 維依賴既有 DSL。

---

## 0. 核心洞見:sign 是唯一本體

**底層只有 sign(form ↔ meaning 的配對)。** 語意/句法/語用不是獨立的層,是 sign 的**內在維度**;型態是 sign 的**組合尺度**;辭典是**已固化 sign** 的視圖;音系/正字法是 sign 的 **phon 維度**的前置約束與後置轉寫。

> **限定(《架構修補01》P2)**:「底層只有 sign」適用於**有意義的單位**;純形式系統知識(共時規則、phonotactics、剖析、轉寫)住 **Grammar Store**,非 sign。判準 = **意義極之有無**:語序約束有意義極,仍是 schema sign,不入 Grammar Store。

**統一兩學派**:構式語法提供**本體**(sign 是實體、多維、可整包表達非組合的習語);生成語法提供**運算**(sign 遞迴組合 → 生產力);**語法化是橋**——一個組合(derivation)被重新分析並固化成一個新 sign(storage)。「運算的固化 = 生成過程變成構式儲存」,正是 construction grammaticalization。

**演化的閉合**:演化只需處理 sign 的 **form / meaning / distribution** 三者變遷 + **組合的固化**。三者分別落在 sign 的 phon 維、sem+prag 維、syn 維(及組合關係);固化落在 entrenchment(§4)。無遺漏。

---

## 1. sign 的特徵結構【M 骨架 / A/B驅動 各維細節】

```
Sign {
    id:    SignId,               // 身分穩定;語法化改變型態但 id 與詞源鏈不變
    phon:  Phon,                 // §2,接既有 DSL
    syn:   Syn,                  // §3,usage-based 輕量 trait
    sem:   Sem,                  // §5,義項網絡節點
    prag:  Prag,                 // 規約化語用;五類開放標記集,入口=pragmatic strengthening(§5b)
    slots: Vec<Slot>,            // 帶槽位 = 抽象 sign(construction);空 = 詞彙 sign
    entrenchment: Entrenchment,  // §4,固著度/頻率;固化程度
}
```

- **morpheme / word / construction 都是 sign**,差別只在抽象度(有無槽位)與組合尺度。不設「型態層 vs 句法層」——同一種 sign,同一種組合(§3.2)。
- **身分穩定、型態可變(呼應 D 的骨架論)**:語法化令一個 sign 沿斜坡改變 phon/syn/型態身分,但 `id` 不變——這是詞源鏈與「化石」(§7)的掛靠點。
- **SignId 是跨節點的 diff 對齊鍵(v0.1.1)**:D 計算兩狀態差異時以 SignId 對齊 sign;借詞產生**新 SignId + origin 指標**指回 donor 的 SignId(不共用 id,詞源跨樹靠 origin 鏈)。
- **phon 可部分指定(v0.1.1)**:抽象 sign(帶槽位構式)的 phon 可空或僅含模板性內容(重音模式、連接音);槽位本身無 phon,由填入的 sign 提供。

## 2. phon 維:接既有 DSL【M】

phon 不是裸音串,是**前受約束、後可轉寫**的維度:

- **前置**:sign 的 phon 必須通過 phonotactics/音系約束(DSL 的 phonotactics 驗證器把關)。
- **本體**:phon 即 DSL 的 autosegmental 表徵(骨架 + 韻律 + 旋律 tier),且明確定義為**底層形 UR**(《架構修補01》P1):表層形永不儲存,由 Grammar Store 共時規則按需導出;phon 的歷時演化 = UR restructuring 或 Grammar Store 編輯。
- **後置**:phon → 正字法,經 DSL 的 romanizer 層。

故音系與正字法**不是與語意平級的層**,是 phon 維度的入口約束與出口轉寫,直接復用 M0 引擎與 DSL strata,無新機制。

## 3. syn 維:usage-based 輕量 trait【M 框架 / A/B驅動 欄位】

### 3.1 定位(經 GPT 建議評估後採納 + 加界)
SYN 比純分佈標籤多一點結構,以 **usage-based** 思想指導,表達力**介於 finite-state 與 CFG 之間**(有界,非全遞迴),形似 **trait / component interface** —— **但加界**:

> SYN 是一組**宣告式、有界**的 trait:每個 sign 宣告少量「提供的範疇」與「需要的槽位(配價)」,槽位帶輕量約束。組合 = 單步匹配,**不做**遞迴約束傳播、類型推導、回溯求解。複雜巢狀交給上層 sign(§3.2),不讓 trait 系統自己遞迴。

此界同 DSL 一貫的「最弱夠用 + 逃生艙」:避免滑向完整 unification grammar(HPSG 等級),因本專案主軸是**演化,非句法推導**。

### 3.2 組合運算【M 概念 / A/B驅動 細節】
生產力 = sign 遞迴組合:一個帶槽位的抽象 sign 把小 sign 填入槽位,產出大 sign(型態尺度與句法尺度為同一運算,只是「詞內/詞外」之別)。組合 = 槽位範疇與填入 sign 範疇的**單步匹配**。非組合習語 = 一個恰好完全指定、無開放槽位的大 sign。

**type/token 區分(v0.1.1,關鍵)**:組合產出的是**暫態 token**,不進 sign 庫;只有 entrenchment 跨閾值(§4)才**固化為儲存的 type(sign)**。否則每次組合都生 sign,庫會被暫態組合灌爆。「造詞」= 手動或生成器直接產出已固化的 sign(略過 token 階段,entrenchment 設高)。

### 3.3 欄位待定【A/B驅動】
SYN 具體宣告哪些欄位(範疇集、配價 arity、槽位約束種類、分佈標籤粒度)**刻意留待造詞(A)與語法化(B)的案例把需求逼出**——過早定死會如早期 tier 般事後大改。§8 列出各實例對 SYN 的預期壓力,作為欄位設計的驗收來源。

## 4. Entrenchment:固化與連續體【M 標記 / B驅動 動力學】

usage-based 核心:高頻共現的組合會**固著(entrench)、chunk 成單位**。這是本專案「連續體而非離散」主線的理論學名:

- **詞/複合/短語是固著度光譜**(實例 5),非離散層邊界。
- **固化 = 一個 sign 從「即時組合」升到「辭典可見」**(§9 辭典視圖);entrenchment 跨過閾值即固化。
- MVP 存**固著度標記**(一個 sign 現在有多固著、是否已固化);**固著的動力學**(頻率如何驅動固化)待語法化引擎(B)。
- **頻率來源(v0.1.1)**:造語工具無真實使用,頻率初值由 A(手動/生成時指派)給;B 的路徑可帶預設頻率變化;真實湧現的使用頻率待 multi-agent。三來源餵同一個 entrenchment 欄位。

## 5. sem 維:帶衍生史的義項網絡【M 骨架 / B驅動 動力學】

對齊 FLEx 的混合模型(entry 掛 sense + semantic domain/lexical relation 網絡),但加**演化邊**:

- 義項之間有**衍生邊**(隱喻 / 換喻 / 窄化 / 寬化),與 D 的 ChangeSet 同構(義項是果,衍生是因)。
- **隱喻固化(實例 7)= 一條衍生邊被標記為「已詞彙化」**——邊的狀態轉換,非新機制。
- MVP 存義項網絡 + 衍生邊 + 固化標記;衍生的自動產生待語法化/語意漂移(B)。

## 5b. prag 維:規約化的語用意義【M 開放標記集 / A/B驅動 細節】

**語言學定位(經連網查證修正)**:prag 維裝的是**規約化(編碼)的語用**——已慣例化、不需推理即攜帶的情境意義;**非**會話推理(那依當下語境、屬理解模組,引擎不存)。在歷時上,它是語法範疇的前身:正沿語法化斜坡下沉、尚未完全變成 syn 的意義。

**入口是機制,非封閉範疇**:語法化的「語用→語法」入口是 **pragmatic strengthening / invited inference 的規約化**(Traugott;Bybee:「語法化中創造語意變化最強的力量是含義的規約化」)——一個**過程**,不是若干固定範疇槽。故 B 只設**一個通用原語** `pragmaticalize`(誘發推理固化),不為每類語用各設機制。pragmaticalization 是否等於 grammaticalization 學界無定論 → **保持形式自由,不強制規範**(最小架構做最多事)。

**五類為開放預設標記集(可刪改)+ B 功能測試種子**,非封閉入口、可重疊:
1. 言說行為(illocution)——語氣、句類;測 say→補語連詞路徑。
2. 人際關係(social deixis)——敬語、T/V;測 register→型態。
3. 信息結構——topic/focus/givenness(Krifka/QUD);測 焦點→語序/標記。
4. 說話者立場(stance)——示證(Aikhenvald)、認識情態、評價;測 subjectification。
5. 指示錨定(deixis)——人稱/時空/話語(Levinson);測 指示詞→冠詞。
五類各對應一條語法化路徑,故兼作 B 的功能測試 fixture。值域取受控本體 prag 分支(§9 同樹,可擴充)。

**可程序化分級(對應干涉光譜:規律自動、文化手動)**:
- **可自動**(有類型學規律/可從結構推導,保留手動覆寫):信息結構(依語序/WALS)、言說行為固化(H&K 路徑)、示證系統結構(Aikhenvald 類型)。
- **需手動框架+自動填充**:敬語尺度(幾級、對誰)手動,形式演化自動(實例 10)。
- **只能手動**(文化/創作,無規律):什麼算正式、禁忌/敬避、褒貶什麼、指示的文化約定 → 入旁註層(§5c)。

規則:語用範疇的**系統/結構**多可自動(類型學規律);其**文化內容**只能手動(虛構文化的創作)。稀疏持有(多數詞彙 sign 無顯著 prag)。

## 5c. 旁註層(Annotation Layer):非形式化知識的家【M】

形式化本體(sign/規則/ChangeSet)之外,增設一個**唯讀旁註層**,掛載無法/不需形式化、供人讀或供生成參考的知識。**唯一變更理由**:掛載非形式化知識。**明確不負責**:不參與 replay(演化引擎看不見它)、不被 diff(非語言狀態)、不約束本體(生成參考是軟提示,可無視)。它是「手動」的純粹保留地——裝那些無規律可自動生成的文化/創作內容。

三類內容(統一為旁註層,不散落):
1. **散文說明**——文化/世界觀/社會自然背景/設計筆記;掛節點/sign/專案。類比 doc comment:附著對象、不影響執行。未來 LLM 接口的天然輸入(Phase 2)。
2. **生成參考**——未固化的隱喻傾向、俗語靈感、風格提示(如「此語言傾向以火喻怒」)。**注意**:已固化的俗語/隱喻**不在此**,它是 idiomatic sign(完全指定、非組合的 construction sign,sem 帶隱喻衍生邊,§5/§1)——本體內;旁註層只放**尚未具體化為 sign 的傾向**,當 Generator/LLM 的軟提示(似 E 先驗:提示非資料)。
3. **使用者語料**——例句、範文、翻譯練習;唯讀。與 docs/11 的**開發驗收案例**區分(那是測試);使用者語料累積後可反哺 usage frequency(接 entrenchment、multi-agent 前的頻率來源)。

旁註層是 C 節點的一部分(隨節點存續),但與四維正交——四維是「語言是什麼」,旁註層是「關於這語言、人寫下的東西」。

## 6. 層作為視圖投影 + 對 D 的 diff 接口【M】

**沒有七個容器,只有 sign 集合 + 投影**:

| 視圖 | 是什麼 |
|---|---|
| 語意 / 句法 / 語用視圖 | 所有 sign 的 SEM / SYN / PRAG 維投影 |
| 型態視圖 | sign 組合運算在「詞內」尺度的呈現 |
| 辭典視圖 | 已固化 sign 的集合(§9) |
| 音系視圖 | sign 的 phon 維(DSL 表徵) |
| 正字法視圖 | phon → romanizer 的轉寫 |

**diff 統一在 sign 上(回應 D §6)**:因層是 sign 的投影,分層差異向量的每個分量都是「同一 sign 集合的某維 diff」,非七套異質函數——phon 距離(形式編輯距離)、sem 距離(義項網絡差異)、syn 距離(trait/構式集合差異)。演化只動 sign,視圖與 diff 自動重算(呼應 D 的 snapshot-replay:單一資訊源)。

## 7. 共時 × 歷時分工【M】

- **C 是共時快照,歷時住在 D 的邊上**(承 D 定案):詞源鏈、語法化史 = D 的 ChangeSet replay,不重複存於 C。
- **化石接口**:共時的「不規則」是歷時的沉積(如 broke)。C 的 allomorph/variant(對齊 FLEx)須能標記「歷時沉積、不由共時規則重新推導」,供 D 的 replay 略過。這是 C/D 的精確分工線上唯一的雙向接口。

## 8. 分裂/裂變的過程態【M 標記 / B驅動 動力學】

Ø(空缺)對齊 Leipzig 標準(語法義務、語音缺席,以 Ø 標記),與 DSL 的 Ø 同源【M】。但「**正在裂變**」超出 Ø:

- 實例 2(自他分化)、9(連接詞分出因果/雖然)要「一個範疇正從一個變兩個、過渡期兩義並存」。
- C 只**預留過程態標記**:一個 sign 可標 `splitting`(指向正分化出的子 sign)或 `merging`(v0.1.1 補:與另一 sign 正在塌縮合一,syncretism/範疇合併——克里奧爾簡化的主力,是 splitting 的對偶);**裂變/合併動力學交給語法化引擎(B)**。同 D 留白生成程序、tier 延後 feature geometry 的克制。

## 9. 範疇系統:可擴充受控本體【M】

對齊 Grambank(195 特徵,多為二元)+ Leipzig(72 範疇標籤)受控詞表,但:

- **受控詞表為底 + 允許自定擴充**;自定範疇(實例 10 的 evidentiality 子類)須**掛回受控本體的某節點**(「我這新範疇是 evidentiality 下的子類」),使自動演化與跨語言比較仍有先驗。
- 範疇值域非自由文字,亦非封閉列舉,而是**帶擴充點的本體樹**。SYN trait 的範疇(§3)取自同一本體樹(v0.1.1)——trait 與受控範疇是同一資訊源。

## 11. 對齊 / 創新 / 演化影響 三向總表

| 問題 | 對齊(既有標準) | 創新(既有工具無) | 演化/語法化的改變 |
|---|---|---|---|
| 層的本質 | FLEx interlinear:實體+投影 | 七維統一投影 | **強制視圖派**:否則 replay/diff 需同步七套 |
| 共同底座 | FLEx 以 morpheme 為底 | sign(form-meaning) | 語法化令身分跨 morpheme/word/affix → 底座須身分穩定的 sign |
| 詞 | FLEx LexEntry/Sense/MSA | — | 詞邊界漂移 → 固著度光譜 |
| 層間關係 | FLEx 用參照 | realize 關係 | 語法化=重新 realize;繼承 DSL 結論 |
| 構式 | 無(FLEx 詞本位) | construction=帶槽位 sign | 構式可語法化 → 與 sign 同級 |
| 語意 | FLEx 混合(sense+網絡) | 帶衍生史的網絡 | 隱喻固化=衍生邊狀態轉換 |
| 共時歷時 | FLEx 近純共時 | C 共時/D 歷時分工 | 化石接口(不規則=歷時沉積) |
| 空缺/裂變 | Leipzig Ø | splitting 過程態 | 裂變=語法化,C 只留標記 |
| 範疇 | Grambank/Leipzig 受控 | 可擴充受控本體 | 演化創造新範疇 → 擴充點掛回標準 |
| diff | 無(FLEx 不演化) | 每維 sign-based diff | 純由演化需求逼出;視圖派使其統一 |
