# 語意錨層本體論(v0.1)— 模組 A/D 交界

回答一個問題:**`sense.concept` 指向的那個「概念網絡節點」到底是什麼?** `ConceptRef` 自 P24 起就存在於引用型別表,但它指向的東西從未被定義——`crates/language/src/lib.rs` 的 `ConceptRef` 至今只是一個 `ref_ty!` 空殼。本檔定義它指向什麼、那東西由誰提供、以及它在歷時中憑什麼保持不變。

> 梯次:【M】MVP /【M+】後 /【N】v-next(僅定接口)。
> 上游:P24(Ref 是屬性值)、P29 + 增修 A 裁定 S(std 與 plugin 同構;std 提供的是語言學分析而非引擎功能)、P30(資料層/程式碼層分界)、P50(lock 與可重現性)、P71-S/R7′/R11/R14(**引擎不得內含語言學**)。
> **本檔新增**:P77–P83(見 §11)。
> **先錨、後投影**:本檔只定座標系;詞向量、語意場視圖、共詞化統計都是其上的唯讀投影(§8),不反向定義座標系。

---

## 0. 核心洞見(統一原則)

**語意沒有物理本體,所以錨層是被規定的;而既然是規定,它就必須可被替換。**

這是語意與音韻的根本不對稱。音變引擎能做,是因為底下有語言外、跨時代不變的基底——人類聲道。IPA 不是約定,是測量。語意沒有這個東西:任何一套概念清單都是某個理論對世界的切分,帶著它自己的偏斜。

從這裡推出兩條,它們合起來就是本檔:

1. **必須有錨**。沒有跨時代不變的座標系,「語意變化」無法被測量,只能被記述;歷時 diff、互通度、跨語言比較全部落空。
2. **錨不可以住在引擎裡**。因為錨是規定,而引擎不該內含任何一種語言學立場——這正是 R7′/R11/R14 已經裁定過的事(`sem.rs` 的三條 bridge 搬進 `std:core`)。**錨族是 package,和 `std:core` 同構,可增可刪可替換。**

判準隨之而來:**一個錨層是好的,若且唯若它讓「同一個變化」在不同語言、不同時代得到同一個編碼。** `HAND → ARM` 這個提喻,發生在語言 A 的 t=200 與語言 B 的 t=900,應落在錨層上的同一條位移。做得到就能用,不管它在哲學上是否「真」。這把一個無解的哲學問題換成了可驗證的工程問題,也給了 §7 的驗收測試一個明確靶心。

## 1. 兩級錨層:骨架與樁點【M】

錨層自己分兩級。混為一談是最容易犯的錯——直接拿三千個 Concepticon ID 當錨,得到的是一份**列表**而不是**座標系**,沒有共詞化資料的兩個概念之間連「近」都定義不出來。

```
骨架 skeleton   由錨族套件提供的封閉節點集合(範疇樹 / 尺度 / 圖)
                跨語言、跨時代不變;是真正的不變項
                ↑ 引擎只認識它的「形」(§3),不認識它的內容

樁點 peg        `concept HAND:` —— 被骨架座標「定義」出來的具名位置
                開放、可增長;`ConceptRef` 指向的就是它
                ↑ 對外可選地錨到 Concepticon / CLICS,身分是外部證據
```

**樁點是被定義的,不是原始的。** 世界長出新的文化概念時,加樁點即可,骨架不動——不變項就真的不變。這條同時解掉了「英語 gloss 汙染」的老問題:**gloss 可以當樁點的可讀別名,不能當骨架**;骨架只由錨族套件的節點集合構成,樁點的名字則和 export 表的 alias 一樣,只是人類可讀層(P29「名字只是別名,底層引用走 stable ID」)。

## 2. 錨族即套件【P77】【M】

**決策:每一族錨是一個獨立 package,走既有的 `code/` `data/` `config/` 三層目錄,不新增任何載入機制。**

`package.conf` 增兩個欄位:

```conf
kind = std
name = ontology
version = 0.1.0
rule_namespace = std:ontology
provides_anchor_family = ontology      # 本套件提供一族錨;缺省=不提供
anchor_family_shape  = tree            # tree | scale | graph(§3)
code = code/ontology.lang
data = data/adjacency.tsv
```

隨之而來的全部是**免費**的,因為 P29 的機制已經在那裡:

| 需求 | 既有機制 | 不需新做 |
|---|---|---|
| 增刪錨族 | 啟用/停用套件(`config/package.conf` 的 `enabled`) | ✓ |
| 替換錨族 | priority 四層:未啟用 < std < plugin < 專案本地 | ✓ |
| 錨族版本鎖 | P50 的 lock——載入什麼就鎖什麼 | ✓ |
| 錨節點穩定身分 | `exports.tsv` 的 `stable_id`,作者改名不斷引用 | ✓ |
| 錨族衝突 | 同名同 priority → warn + 強制消歧 `std:ontology::Animate` | ✓ |

**判準沿用 P30**:錨族的**節點與拓樸**會被 compile,住 `code/*.lang`;**共詞化權重、語義地圖鄰接的經驗數值**只被查表,住 `data/*.tsv`。

**`std:core` 的既有語意範疇樹就是錨族 `ontology` 的既有部分。** `code/ontology.lang` 裡的 `Semantic` / `Entity` / `Relation` / `Physical` / `Animate` / `Human` / `Event` / `Motion` 已經是一棵 `belongs` 樹,形狀正確。**原地宣告為錨族,不搬檔**——搬檔會斷掉 `exports.tsv` 既有的 `std:core:*` stable ID,而 P29 明訂 stable ID 是唯一穩定契約。新增的四族另立新套件。

## 3. 引擎只認識三種族形【P78】【M】

這是「引擎不得內含語言學」在錨層的具體兌現:引擎不知道 `Animate` 是什麼,只知道它是某棵樹上的一個節點。

| 族形 | 節點關係 | 引擎提供的唯一運算 | 複雜度 |
|---|---|---|---|
| **tree** | `belongs` 構成的分類樹 | 最近共同祖先深度(Wu-Palmer 形) | O(depth) |
| **scale** | 有序枚舉 | 序位差 | O(1) |
| **graph** | `data/` 的加權鄰接表 | 最短路 / 鄰接查詢 | O(E log V) |

**三種形涵蓋全部五族**(§9),而且都不含任何語言學知識:引擎只做樹走訪、序位相減、圖搜尋。**新增一族 = 加一個套件;新增一種族形 = 改引擎**——後者是刻意設得很貴的,以免族形集合被無節制擴張成通用查詢語言(沿 P22 三道界的精神)。

## 4. `concept` 宣告與 `ConceptRef`【P79】【M】

樁點是 Language AST **定義類**(修補 05 §10.3 ①)的新節點型別。這是本檔唯一的新語法,且刻意只有一個關鍵字:

```
concept HAND:
    belongs Physical              # → std:ontology(tree)
    belongs PART_WHOLE            # → std:schema  (tree)
    dim animacy = inanimate       # → std:semdim  (scale)
    ref concepticon:1277          # 外部證據,可選,非真相來源
```

**錨定一律走 `belongs` 與 `dim`,零新機制**——`belongs` 是 `std:core` 已在用的既有詞,`dim` 是 scale 族的賦值形。一個樁點可以同時掛在任意多族上;掛在哪些族由**已啟用的套件**決定,引擎不預設任何一族為必需。

**決策:`ConceptRef` 綁定不可變。**

理由是可重現性,不是哲學。歷時 function 的條件語法會匹配 `target.sem.concept == GO`(修補 05 §10.1)。若 concept 綁定可隨 drift 滑動,規則的匹配基礎就會在 replay 中改變,P26 的「同 ChangeSet replay N 次逐位元相同」失守。故:

| 操作 | 對錨層做什麼 | 邊界 |
|---|---|---|
| `drift{direction}` | 改 `sense.meaning`——**在既有 concept 的座標鄰域內移動** | 不改 `sense.concept` |
| `derive_sense{kind}` | **新增 sense,綁新 concept**,加衍生邊 | 跨概念的移動一律走這裡 |

代價是「意義的漸變」在系統裡被離散化成一串小事件。這不是妥協:歷時語義學本來就認為義項的產生是 reanalysis,是離散的。而它換來的是與 `chg` 授權模型一致的性質——**變化是有型別的離散事件,不是連續的數值滑動**,因此可逆、可審計、可重放。

## 5. 距離分族計算,不得混算【P80】【M】

**決策:跨族距離不存在預設定義。** 引擎回傳的是一個**分族向量**,不是純量:

```rust
struct AnchorDistance {
    per_family: BTreeMap<AnchorFamilyId, f32>,   // 每族一個值,族形決定算法
}
```

要塌成純量,必須由呼叫端**顯式宣告**權重。五族不同構——把「本體範疇差兩層」和「animacy 差一階」加起來得到的數字沒有意義,而一旦它有了預設值,它就會被到處使用並被當成真的。

這同時是 §0 判準的必要條件:分族保留才能表達「`HAND → ARM` 在 ontology 族上位移為 0、在 schema 族上是一條 PART_WHOLE 邊」——**位移的型別**,而不只是位移的大小。純量距離會把隱喻、轉喻、廣化、窄化全壓成同一個數,而那正是歷時引擎唯一在乎的區別。

## 6. 錨層版本與遷移【P81】【M】

**決策:錨族套件版本進 lock;錨族改版是顯式遷移事件,不得靜默。**

這條沒有新機制,P50 已經給了:載入什麼就鎖什麼。要補的只有一條約束——

**錨族套件的 major 版本變動 = 座標系變動 = 所有既有測量值失效。** 若骨架悄悄改了,所有歷史 diff、互通度、語意場投影會靜默地變成另一個數字,而沒有任何東西報錯。故:

- Evolution_node 的 lock 記錄啟用錨族的**版本與內容雜湊**(復用《套件內容雜湊的正規化 v0.1》)。
- lock 中錨族雜湊不符 → **拒絕 replay 並要求顯式遷移**,比照 P34 History 驗證的失敗處置,不 panic、分級回報。
- 遷移本身是一份 ChangeSet(樁點重新 `belongs`),因此可審計、可 replay、可回退。

## 7. 空錨層必須可運行【P82】【M】

**決策:不啟用任何錨族時,引擎必須完整運作;失去的是比較能力,不是執行能力。**

這條直接對映 §8.2 已經做過的實測(完全不給 std、只用自訂 trait 樹 → 建構診斷 `[]`、closure 正常、`check_language` 零錯誤)。錨層加進來後這個性質**不得退化**。

驗收測試(列入 CI,與雙軌迴歸同級):

| 測試 | 期望 |
|---|---|
| 零錨族載入 → compile + replay | 通過;`concept` 宣告僅存名字,`belongs`/`dim` 標為未解析但不報錯 |
| 零錨族 → `AnchorDistance` 查詢 | 回傳空 `per_family`,**非** 0.0,非錯誤 |
| 換掉 `std:ontology` 為自訂族 | 全流程通過;既有 `.chg` 只要不引用被刪節點即不斷 |
| §0 判準測試 | 同一提喻在兩個語言、兩個年代 → 分族向量逐位元相同 |

最後一項是 §0 判準的可執行版本,也是判斷「這套錨到底行不行」的唯一客觀依據。

## 8. SemanticBackend 契約【P83】【M+】

`SemanticBackend` 自《總鳥瞰》起就標為 must-have 且**必須可 stub**(否則 drift 測試不確定),P30 判它為 Registry 後端(數值運算,P22 明文禁止進資料層)。本檔補上它的定義域:

**決策:SemanticBackend 只能在已啟用錨族給定的座標系內計算,不得自帶座標系。**

```rust
trait SemanticBackend {
    /// 在 anchor 給定的座標系內,計算 drift 後的新 sense 位置。
    /// 不得回傳落在座標系外的值;不得改變 concept 綁定(P79)。
    fn drift(&self, sense: &SenseView, dir: DriftDirection, anchor: &AnchorSpace)
        -> Result<SenseMeaning, BackendError>;
}
```

三條契約:

1. **值域封閉**:回傳值必須可用啟用中的錨族座標表達。落在座標系外 → `check_language` 分級回報,不 panic。
2. **不得越過 concept 邊界**:那是 `derive_sense` 的職責(P79)。
3. **可 stub 且決定性**:stub 實作回傳恆等或固定小位移,使 drift 的 golden test 不含隨機——比照 P26 的決定性要求。

**詞向量在這裡,而且只在這裡。** 一個 embedding 後端是 `SemanticBackend` 的**一種實作**,是投影工具,不是真相來源。它的本體(分布式/差異式)沒有錨、旋轉不變,故無法跨時代或跨語言比較——歷時詞向量必須靠 orthogonal Procrustes 對齊,而對齊的前提是「多數詞沒變義」這個統計假設。那不是測量,是把缺席的錨層用假設臨時補上。本檔的錨層存在的意義就是**不需要那個假設**。

## 9. std 錨族套件清單【M / M+】

| 套件 | 族形 | 內容 | 量級 | 錨住什麼 | 梯次 |
|---|---|---|---|---|---|
| `std:core`(既有) | tree | 本體範疇:Entity / Event / Relation / Physical / Animate / Human… | ~10 | 最頂層「這是哪種東西」 | 【M】原地宣告 |
| `std:schema` | tree | 具身圖式:CONTAINER / PATH / SOURCE-PATH-GOAL / CONTACT / SUPPORT / BLOCKING / PART-WHOLE(image schema + Talmy 力動態) | ~30 | 空間,及一切由空間隱喻而來的抽象義 | 【M】 |
| `std:semdim` | scale | 義素維度:animacy / concreteness / boundedness / control / valence / telicity | ~40 | 詞彙內部細分;可壓 bitmask | 【M】 |
| `std:semmap` | graph | 功能位置:語義地圖概念空間節點(TAM、格/論旨、情態、指示) | ~60 | **語法意義**——概念清單覆蓋不到的那塊 | 【M+】 |
| `std:aktionsart` | tree | 事件結構:state / activity / achievement / accomplishment + proto-role 蘊含 | ~15 | 動詞與論元結構 | 【M+】 |

兩點說明:

**`std:schema` 是關鍵族,因為它解釋方向性。** 它不只分類,還說明為什麼隱喻總是具體→抽象、空間→時間,為什麼 `GO → FUTURE` 而不是反過來。`derive_sense{kind: metaphor}` 需要一個東西來判斷某個隱喻是否可信——就是它。

**`std:semmap` 與既有 `std:grammaticalization` 互補。** 後者已經是路徑庫(P29 已定的落點,Heine & Kuteva 形,住 `code/*.chg`);前者是那些路徑**行經的座標**。兩者分屬 code 的兩種角色:一個是變化的 function,一個是變化的空間。

**具身圖式那族假設了「人類尺度的身體」。** 若專案的世界有非人說話者,這是個要有意識關掉或替換的旋鈕——而它之所以可關,正是因為 P77 把它做成了套件。

## 10. 與既有 Atomic Rewrite 的接合【M】

12 項 Atomic Rewrite 仍是封閉內建集(P16),本檔不增不減,只補上它們在錨層上的語意:

| Rewrite | 錨層語意 |
|---|---|
| `drift{direction}` | concept 不變,`sense.meaning` 在座標鄰域內移動(§8) |
| `derive_sense{kind: metaphor}` | 新 concept;`std:schema` 上應存在一條跨域對映 |
| `derive_sense{kind: metonymy}` | 新 concept;同一 `SemanticFrame` 內的角色位移 |
| `derive_sense{kind: broaden/narrow}` | 新 concept;`std:core` 樹上的上移/下移 |
| `lexicalize_sense` | 錨層不動;衍生邊 → opaque |
| `adopt` | 借入 sign 的 sense 必須綁**現有**樁點或顯式新增樁點,不得產生懸空 `ConceptRef`(P24 不變量) |

最後一條是 P24「懸空 Ref」不變量在錨層的延伸,`check_language()` 應納入檢查。

## 11. P 系列決策(本文件新增)

| 編號 | 決策 |
|---|---|
| **P77** | **錨族即套件**:每族錨是獨立 package,走既有 `code/`/`data/`/`config/` 三層與 P29 載入機制;`package.conf` 增 `provides_anchor_family` / `anchor_family_shape` 兩欄;增刪錨族=啟用/停用套件,替換=priority 四層,版本鎖=P50 lock,穩定身分=`exports.tsv` stable ID——**零新載入機制**;`std:core` 既有語意範疇樹原地宣告為錨族 `ontology`,**不搬檔**(搬檔會斷 stable ID) |
| **P78** | **引擎只認識三種族形**:`tree`(LCA 深度)/`scale`(序位差)/`graph`(最短路);引擎不知道節點是什麼,只做樹走訪、序位相減、圖搜尋——R7′/R11/R14「引擎不得內含語言學」在錨層的兌現;**加一族=加套件,加一種族形=改引擎**(刻意昂貴,防族形集合擴張成通用查詢語言) |
| **P79** | **`concept` 宣告 + `ConceptRef` 綁定不可變**:樁點為 Language 定義類新節點,錨定一律走既有 `belongs` 與新增的 `dim`(唯一新語法);樁點被骨架座標定義,gloss 只是可讀別名;**`drift` 只在概念鄰域內移動、`derive_sense` 才跨概念**——理由是 P26 決定性 replay,非哲學 |
| **P80** | **距離分族計算,不得混算**:`AnchorDistance` 回傳 `per_family` 向量而非純量;塌成純量必須呼叫端顯式宣告權重,**無預設值**;保留分族才能表達位移的**型別**(隱喻/轉喻/廣化/窄化),純量會把它們壓成同一個數 |
| **P81** | **錨層版本進 lock,改版是顯式遷移事件**:lock 記錄錨族版本與內容雜湊(復用套件內容雜湊正規化);雜湊不符→拒絕 replay 並要求顯式遷移,分級回報不 panic;遷移本身是一份 ChangeSet(樁點重新 `belongs`),故可審計可回退;**防止骨架靜默改動導致所有歷史測量值靜默改變** |
| **P82** | **空錨層必須可運行**:零錨族時 compile/replay 完整通過,`concept` 的 `belongs`/`dim` 標未解析但不報錯;`AnchorDistance` 回空 `per_family` 而非 0.0;四項 CI 驗收(含「同一提喻跨語言跨年代 → 分族向量逐位元相同」= §0 判準的可執行版本) |
| **P83** | **SemanticBackend 定義域封閉**:只能在已啟用錨族給定的座標系內計算,不得自帶座標系;三條契約=值域封閉(越界走 `check_language` 分級回報)、不得越過 concept 邊界、可 stub 且決定性;**詞向量後端是此 trait 的一種實作=投影工具,非真相來源**(其本體無錨、旋轉不變,跨時代比較須靠 Procrustes 對齊,而對齊前提是統計假設不是測量) |
