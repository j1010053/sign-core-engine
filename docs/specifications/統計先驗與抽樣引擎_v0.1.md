# 統計先驗與抽樣引擎本體論(v0.1)— 模組 E

E 是 A(Generator 補全)、B(路徑自然度)、文法檔(自動模式)的統計來源。經需求倒推(「E2 為了做到什麼」之辯)後,E 的最終形態:**一個唯讀類型學先驗庫(E1)+ 一組無狀態統計/抽樣函數;不存在獨立儲存的「語言頻率模型」——語言特定頻率是 sign 集合的投影,手動/導入的調整住在節點的覆寫層。**

> 梯次:【M】MVP /【M+】後 /【N】v-next。上游:07(sign)、08(B 原語)、09(Generator)、CLAUDE.md §6(命名規約)。

## 0. 職責契約(唯一變更理由)

| 部件 | 唯一變更理由 | 明確不負責 |
|---|---|---|
| **E1 先驗庫** | 內建類型學資料如何組織與查詢 | 不存語言特定資料、不抽樣、不隨專案變(唯讀、隨軟體發版) |
| **統計投影** | 如何從 sign 集合數出頻率 | 不儲存結果(按需計算;單一資訊源=sign 集合) |
| **抽樣函數** | 如何從有效分佈 seeded 抽樣 | 不做硬約束(phonotactics 過濾在 phon 維/DSL)、不擁有分佈 |
| **覆寫層**(資料,住 C/D 節點) | 使用者對分佈的手動/導入調整 | 不屬於 E;E 唯讀之。可 diff、可繼承、被 D 快照 |

E 整體**無狀態、不擁有任何語言資料**——God Module 風險為零。

## 2. 有效分佈:優先序棧【M】

任一抽樣所用的「有效分佈」由四層疊加,**高優先者逐項覆蓋低優先者**(未覆蓋項落到下一層):

```
手動逐項覆寫          ← 使用者個別調(「/k/ = 0.15」)
  > 導入 provider 分佈 ← 整份注入(見 §3)
  > 統計投影           ← 從本節點 sign 集合即時數出(預設;單一資訊源)
  > E1 先驗            ← 冷啟動(sign 尚少時)
```

- **投影是預設基底**:未被覆蓋的項永遠即時反映 sign 集合,隨演化自動更新。
- **覆寫層(手動+導入)是稀疏 delta**,住 C/D 節點(語言資料):可 diff、被子語言繼承、被 D 快照;E 唯讀。
- 冷啟動:新語言 sign 少,投影空 → 落到 E1 先驗;sign 累積後投影自然接管。

## 3. DistributionProvider:導入接口【M 介面 / 實作分梯】

覆寫層接受「整份分佈注入」,來源為可插拔 provider(同 DSL strategy/D28、SemanticBackend 的模式):

```
trait DistributionProvider { fn distribution(&self, domain) -> WeightTable }
實作:NaturalLanguage(從 PHOIBLE/語料統計某真實語言,如「音感像西班牙語」)【M+】
     OtherNode(借另一 conlang 節點的投影——方言/姊妹語參考)【M】
     TypologicalPrior(E1 某類型傾向)【M】
     Manual(逐項,最高優先)【M】
```

- **導入 = 複製 snapshot 進節點覆寫層**,非外部活連結——可重現性與離線性不破。
- **界線**:導入只影響抽樣權重,**不碰 phonotactics 硬約束**(phon 維/DSL 自有)。「接西班牙語分佈」= 頻率像西語、音節合法性仍由本語言 phonotactics 決定。頻率借來、結構自訂。

## 4. 抽樣與過濾【M】

- **seeded 加權抽樣**:注入式 PRNG(`rand_chacha` 的固定 `ChaCha20Rng`),同 seed、同 ordered weights 得同結果;無狀態純函數 `sample(effective_dist, seed, n) -> candidates`。演算法名稱進 selection trace,升版必須顯式改 golden。
- **純頻率 + 事後過濾**:E 只管加權抽樣;硬約束(音位配列)由既有 phonotactics 驗證器過濾抽樣結果。兩職責分立——E 不碰約束、驗證器不碰頻率。
- 統計投影函數族:`project_phoneme_freq(signs)`、`project_syllable_shapes(signs)`、`project_category_usage(signs)`……全部按需計算、不快取(sign 數量級小;快取列【M+】,同 memoize 待遇)。
