# 統計先驗與抽樣引擎本體論(v0.1)— 模組 E

E 是 A(Generator 補全)、B(路徑自然度)、文法檔(自動模式)的統計來源。經需求倒推(「E2 為了做到什麼」之辯)後,E 的最終形態:**一個唯讀類型學先驗庫(E1)+ 一組無狀態統計/抽樣函數;不存在獨立儲存的「語言頻率模型」——語言特定頻率是 sign 集合的投影,手動/導入的調整住在節點的覆寫層。**

> 梯次:【M】MVP /【M+】後 /【N】v-next。上游:07(sign)、08(B 原語)、09(Generator)、CLAUDE.md §6(命名規約)。

## 0. 職責契約(唯一變更理由)

| 部件 | 唯一變更理由 | 明確不負責 |
|---|---|---|
| **E1 先驗庫** | 內建類型學資料如何組織與查詢 | 不存語言特定資料、不抽樣、不隨專案變(唯讀、隨軟體發版) |
| **統計投影** | 如何從 sign 集合數出頻率 | 不儲存結果(按需計算;單一資訊源=sign 集合) |
| **抽樣函數** | 如何從有效分佈 seeded 抽樣 | 不做硬約束(phonotactics 過濾在 phon 維/DSL)、不擁有分佈 |
| **覆寫層**(資料,住 C/D 節點) | 使用者對分佈的手動/導入調整 | 不屬於 E;E 唯讀之。可 diff、可繼承、被 D 快照 |

E 整體**無狀態、不擁有任何語言資料**——God Module 風險為零。

## 2. 有效分佈:優先序棧【M】

任一抽樣所用的「有效分佈」由四層疊加,**高優先者逐項覆蓋低優先者**(未覆蓋項落到下一層):

```
手動逐項覆寫          ← 使用者個別調(「/k/ = 0.15」)
  > 導入 provider 分佈 ← 整份注入(見 §3)
  > 統計投影           ← 從本節點 sign 集合即時數出(預設;單一資訊源)
  > E1 先驗            ← 冷啟動(sign 尚少時)
```

- **投影是預設基底**:未被覆蓋的項永遠即時反映 sign 集合,隨演化自動更新。
- **覆寫層(手動+導入)是稀疏 delta**,住 C/D 節點(語言資料):可 diff、被子語言繼承、被 D 快照;E 唯讀。
- 冷啟動:新語言 sign 少,投影空 → 落到 E1 先驗;sign 累積後投影自然接管。

## 3. DistributionProvider:導入接口【M 介面 / 實作分梯】

覆寫層接受「整份分佈注入」,來源為可插拔 provider(同 DSL strategy/D28、SemanticBackend 的模式):

```
trait DistributionProvider { fn distribution(&self, domain) -> WeightTable }
實作:NaturalLanguage(從 PHOIBLE/語料統計某真實語言,如「音感像西班牙語」)【M+】
     OtherNode(借另一 conlang 節點的投影——方言/姊妹語參考)【M】
     TypologicalPrior(E1 某類型傾向)【M】
     Manual(逐項,最高優先)【M】
```

- **導入 = 複製 snapshot 進節點覆寫層**,非外部活連結——可重現性與離線性不破。
- **界線**:導入只影響抽樣權重,**不碰 phonotactics 硬約束**(phon 維/DSL 自有)。「接西班牙語分佈」= 頻率像西語、音節合法性仍由本語言 phonotactics 決定。頻率借來、結構自訂。

## 4. 抽樣與過濾【M】

- **seeded 加權抽樣**:注入式 PRNG(`rand_chacha` 的固定 `ChaCha20Rng`),同 seed、同 ordered weights 得同結果;無狀態純函數 `sample(effective_dist, seed, n) -> candidates`。演算法名稱進 selection trace,升版必須顯式改 golden。
- **純頻率 + 事後過濾**:E 只管加權抽樣;硬約束(音位配列)由既有 phonotactics 驗證器過濾抽樣結果。兩職責分立——E 不碰約束、驗證器不碰頻率。
- 統計投影函數族:`project_phoneme_freq(signs)`、`project_syllable_shapes(signs)`、`project_category_usage(signs)`……全部按需計算、不快取(sign 數量級小;快取列【M+】,同 memoize 待遇)。

| 梯次 | 項目 |

## 6. 增修 A:三層棧、IPA 鍵、注入式過濾器、評分不定義

> **狀態:已裁定**(擁有者 2026-08-04),步驟 19 實作依本節。
> 本節不改 §1 的資料來源清單與 §4 的職責分工,只收窄 §2 的棧與 §5 的【M】範圍。

### 6.1 有效分佈降為三層——**投影退出抽樣**

§2 原訂四層。**統計投影自抽樣棧移除**:

```
手動逐項覆寫    ← 使用者個別調(「/k/ = 0.15」)
  > 導入 provider ← 整份注入(§3)
  > E1 先驗       ← 基底
```

投影**照做但改變用途**:接 `邏輯分層架構` §3.2 早已列出的
`query::phoneme_stats(node_id)`,作為**唯讀報表**給使用者參考,
抽樣器不看。職責因此更乾淨:E 提供數字、UI 顯示、抽樣器不依賴它。

**代價**(明列,不迴避):分佈不再隨語言演化自動更新;步驟 19 的出口
「造詞**像這個語言**」弱化為「像**使用者宣告的分佈**」。

**可逆**:投影原本位居第三層,移除後 E1 上遞為基底;日後要加回,是在
provider 與 E1 之間**插一層**,對介面純增量,不回頭改既有東西。

**連帶消解**(不必再裁):投影數 UR 還是表層、要不要以 `entrenchment` 加權、
type 還是 token frequency——當它只是報表,可先給最直白的一種(數 UR 的音素
出現次數),日後要別的口徑就多一欄,無人依賴故不會壞。冷啟動的回退粒度同理
消失:三層都是顯式提供的資料,回退只是 map lookup。

### 6.2 鍵空間 = **IPA 字串**

三個來源(E1 / provider / 手動)共用一組鍵,鍵為 IPA 字串
——PHOIBLE 的 segment 欄本來就是 IPA,且三者皆為 TSV,對齊是資料的事。

**不用 `SymId`**:那是 tshiatun 引擎側的 intern 結果,拿它當跨語言先驗的鍵
會把 E 綁進引擎。

### 6.3 phonotactics 過濾器 = **注入式 trait**

§4 的分工不變(E 只管加權,硬約束事後過濾),但過濾器**不由 `generate` 直接
依賴**——它住 tshiatun submodule,而 `generate` 不依賴引擎。改為:

```rust
pub trait PhonotacticFilter { fn admits(&self, phon: &str) -> bool; }
```

實作由呼叫端提供(住已有 tshiatun 依賴的那一層)。得到:`generate` 零引擎依賴、
「不同語言不同 phonotactics」天然成立、測試可塞兩行假實作。

與 crate 內既有形狀一致(`Strategies`、§3 的 `DistributionProvider`、DSL 的 D28),
**不是新機制**。

### 6.4 評分:引擎**不定義**合成公式

`Sign生成引擎本體論` §3 說「Proposal 帶評分(音韻/文化/詞頻分量)」,
折磨 12 的判決是 ⚠️(待補定義)。**裁定:該定義不補,永久擱置。**

`Proposal::score` 保留,但**引擎不規定它怎麼算**——各 Generator 自行決定並填入
一個數;引擎只拿它排序(手動模式)或作抽樣權重(自動模式)。

理由:合成方式是提議者的事(§3「**排序是提議側的事**」);而文化分量另有既有
約束——CLAUDE.md §2 明訂旁註層「不參與 replay、**不約束生成**(軟提示)」,
若把它寫進引擎級的評分公式,它就在約束生成了。

### 6.6 投影的切分依**給定音素清單**,最長匹配

多字元 IPA 音段(塞擦音 `t͡ʃ`、帶附加符號者)必須整段算,否則 `t͡ʃa`
會被拆成三個「音素」。

**清單由呼叫端提供**,不由 `stats` 自行抓取:`Language` 的 dsl 域宣告
(`Symbol k` 那些行)是**不透明 verbatim 字串**(I15-a / 裁決 1),`language`
刻意不解析,`stats` 更不得越界去 parse。與 `PhonotacticFilter`、
`DistributionProvider` 同一個注入模式。

最有用的清單是**有效分佈的鍵集**——報表與抽樣用同一組鍵,
「我的語言實際用多少 / 先驗說該用多少」才對得起來。

兩個刻意的行為:

- 清單為空 → 退回**逐字元**切分(尚未宣告清單時報表仍可用);
- 匹配不到的字元 → **以該字元自成一鍵計入**,不丟掉。這樣「本語言用了不在
  清單裡的音段」會在報表上現形,那是撰寫錯誤的訊號。
