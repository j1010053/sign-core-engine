## 0. 修補摘要(一段話)

DSL 誕生於「詞表演化」世界觀(語言=詞表,演化=對詞表套規則)。sign 本體確立後,正確世界觀是:**語言 = sign store(底層形,有限)+ Grammar Store(共時 deep-to-surface 規則,有限);表層形按需導出、永不儲存;歷時演化 = 編輯這兩個有限儲存,永不觸碰無限的組合空間。** `Word` 從「儲存單位」改職為「臨時韻律域」(預覽/拼讀時由 sign 組合臨時建構)。**表徵、規則語言、單規則執行語意完全不變**——變的只是規則的居所與觸發時機(組織層)。

## 1. 新架構(定稿圖)

```
【儲存,皆有限】
sign.phon            = 底層形 UR(詞根/詞綴)
construction.phon    = 模板 + 可選 cophonology(構式專屬小規則組)
Grammar Store        = 按韻律層級索引的共時規則,節點的第二個一等儲存
                         stem-level  (詞幹層,循環套用)
                         word-level  (ω 層,整詞後)
                         phrase-level(φ/ι/U 層 = surface sandhi,spell-out 時跑)

【導出,即時、永不儲存】
component 組合樹 → 臨時 Word(韻律域,七層:μ σ Ft ω φ ι U)
  → 循環:stem-level(逐組合環,含觸發構式的 cophonology)
  → word-level(ω)
  → spell-out:phrase-level(純函數約束不變)
  → 表層形(token;僅跨 entrenchment 閾值者固化回 store)

【歷時,D 的 ChangeEntry,操作有限對象】
編輯 Grammar Store:AddRule / LoseRule / ReorderRules / InvertRule
L3 搬遷宏(生命週期):
  Phonologization   歷時音變 → 安裝為共時規則(AddRule)
  Morphologization  規則從 Grammar Store 搬進構式 cophonology
  Lexicalization    表層烤進 UR + LoseRule(= lexical sandhi 的機制)
```

**sandhi 二型的最終歸宿**(取代先前「規則標 lexical|surface」方案,更乾淨):
- surface sandhi = Grammar Store 的 phrase-level 規則,每次 spell-out 導出、永不回寫。
- lexical sandhi = 歷時的 `Lexicalization` 宏(烤進底層 + 刪規則),一次性事件。

**防爆炸閂**:cophonology 僅兩種來源——使用者手動、或 `Morphologization` 宏;自動演化不得憑空為任意子類建 cophonology(文獻警告:可切分的子模式數量無限)。

**多式綜合/組合爆炸的根治**:歷時演化編輯有限的 Grammar Store 與有限的 UR;無限組合的表層永遠即時導出。對詞根寫音變 → 得到:UR 改寫(若 restructuring)或規則入 Grammar Store + 取樣預覽 + 少數已固化長詞實際更新。

## 3. 實作插入順序(配合「M0 步驟二進行到一半」)

**核心事實:本修補對 M0 步驟 2–3 零衝擊**——primitives/lifecycle/verbs 是「單條規則如何作用於一個 Word」,與規則住哪無關。故:

| 時點 | 動作 | 理由 |
|---|---|---|
| **現在(步驟 2 中)** | **照原計畫做完步驟 2,不插任何新內容** | 六原語+生命週期與本修補正交;中途改道只會失去測試出口 |
| 步驟 3(verbs 第一批) | 照原計畫,8.1 綠燈 | 同上 |
| **步驟 4(dsl parser)** | **唯一的 M0 內插入點**:規則檔語法加 `level: stem\|word\|phrase` 標記(預設 word);韻律宣告支援七層(φ ι U 先只是合法名,無行為) | parser 是新語法唯一入口;現在加標記=零成本,之後加=改檔案格式。8.1–8.6 全是詞內,預設 word 即可跑,行為不變 |
| 步驟 5 | 照原計畫(spread/shift/locality/lazy) | 零衝擊 |
| **步驟 6(scan/spellout)** | spellout 加一個 **phrase-level 規則掛鉤**(接受一組規則,MVP 傳空集) | 為 surface sandhi 預留插座;空集=行為同現版,不擋 8.6 |
| **M0 收工後(新增步驟 8)** | **Grammar Store 容器**:規則的具名儲存(按 level 索引)+「(Store+詞)→導出」的 API;把 M0 的批次跑改寫為「AddRule+Lexicalization 相容模式」 | 這是本修補的本體,但它不依賴 M0 內部,是包在外面的組織層;M0 全綠後做,有完整迴歸網 |
| Sign 引擎實作時 | 臨時 Word 建構(組合樹→韻律域)+ **循環套用** + construction cophonology 槽 | 循環由 component 樹驅動,沒有 sign 組合就無從循環;自然落在 sign 引擎階段 |
| D 實作時 | ChangeEntry 的 Grammar Store 編輯語意 + 三個生命週期宏 | D 的本份 |

**一句話**:你現在**什麼都不用改**,做完步驟 2、3;步驟 4 加一個 level 標記(預設 word)、步驟 6 留一個空掛鉤——M0 其餘照舊全綠;Grammar Store 本體是 M0 之後的「步驟 8」,循環套用等 sign 引擎。修補的重量全在組織層,M0 的引擎核心一行不改。

## 4. P 系列決策表(本文件為權威存放處)

P 系列 = 架構修補層決策,與 M0 實作層 I 系列(docs/05 §9)平行;引用格式同 D/A/B/C/I。

| 編號 | 決策 |
|---|---|
| P1 | **Word = 臨時韻律域**:`Word` 非儲存單位,由 sign 組合按需建構(預設 ω,sandhi 擴至 φ/ι/U);表層形按需導出、永不儲存 |
| P2 | **Grammar Store 為節點第二個一等儲存**:共時 deep-to-surface 規則按韻律層級索引(stem/word/phrase);「住 sign store 還是 Grammar Store」的判準 = **意義極之有無**(語序約束有意義極 → schema sign;純形式系統知識 → Grammar Store);歷時演化 = 編輯兩個有限儲存(AddRule/LoseRule/ReorderRules/InvertRule + UR restructuring),永不枚舉組合空間 |
| P3 | **strata 層級錨定 + 循環套用**:規則/段落標 `level: stem\|word\|phrase`(預設 word);層疊套用由 component 組合樹驅動(逐環 stem-level 含 cophonology → 整詞 word-level → spell-out 跑 phrase-level);單規則生命週期(執行語意 §1)不變 |
| P4 | **cophonology 雙來源閂**:construction 的 cophonology 槽僅兩種來源——使用者手動、或 `Morphologization` 宏;自動演化不得憑空為任意子類建 cophonology |

生命週期三宏(L3):`Phonologization`(歷時音變→AddRule)、`Morphologization`(規則→構式 cophonology)、`Lexicalization`(表層烤進 UR + LoseRule);sandhi 二型歸宿見 §1。
