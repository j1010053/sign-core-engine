# 直譯器執行語意 & Spell-out — 決策待辦清單

供逐條裁決。定案後併入《執行語意規格》,直通 M0。標記:🔴 卡動工(必須現在定) / 🟡 有預設可先跑 / 🟢 界線判斷。
格式:**問題** → 選項 → ⭐建議 → 影響。

---

## A 組｜🔴 硬核(定義確定性,不定引擎無法確定運作)

### A1. 單規則套用模型:同時 vs 逐步
一條規則掃過一個詞,所有符合位置是同時改(以套用前狀態判斷全部),還是逐步改(改完一個、下一個看更新後狀態)?
- 選項:(a) 一律同時;(b) 一律逐步;(c) **預設同時,可標 `iterative`**;(d) 預設同時,但 `spread` 類連鎖操作內建逐步。
- ⭐建議 **(d)**:一般改寫同時(合 SPE 直覺、避免意外自我餵食),`spread`/`shift` 這種本質連鎖的操作內建逐步,不需使用者標。
- 影響:所有 tier 內規則的結果;與 A2 綁定。

### A2. 掃描方向與套用點
逐步時的連鎖方向;同時時方向是否仍有意義(如環境判斷的偏好)。
- 選項:(a) 預設 `ltr`,可標 `rtl`;(b) 無預設,連鎖類必須顯式方向。
- ⭐建議 **(a)**:預設 `ltr`;`spread`/`shift` 已強制顯式方向(D10),故只有這兩類以外的逐步規則會用到預設。
- 影響:A1(d) 下僅少數規則涉及;仍需定死避免歧義。

### A3. lazy reparse 的觸發判準(你先前留的坑)
`reparse: lazy` 說「唯讀查詢韻律結構時才重剖」,但「查詢」邊界模糊:修復動詞的 selector 本身也在讀結構。
- 選項:(a) **動詞類型決定**——修復動詞(dominate/release/merge/delete on prosody)整條不觸發重剖,即使其 selector 讀了 stale 結構;(b) 存取類型決定——任何 selector 讀 stale 結構就觸發,修復動詞也不例外。
- ⭐建議 **(a)**:動詞類型決定。唯有如此,補償性延長的空莫拉能在被 `dominate` 修復前存活(8.4 範例才成立)。代價:使用者須知道「修復動詞看到的是 stale 結構」,寫進文件。
- 影響:補償性延長、任何利用暫態病理結構的音變;是本清單語言學後果最大的一題。

### A4. NCC 檢查時機與警告生命週期
違反不交叉發警告不失敗(D7),但何時查?交叉被後續規則解掉要不要收回警告?
- 選項:(a) 每 `associate` 後立即查;(b) **每條規則後查**;(c) 延到 spell-out 才查。是否收回:收回 / 不收回。
- ⭐建議 **(b) + 不收回**:每條規則邊界查(能定位「哪條規則造成」,又不對規則內暫態誤報);警告不收回但標「後續已解除」狀態,保留除錯痕跡又不誤導。
- 影響:警告系統的實作與追蹤視圖;與 B5 警告分級表相接。

## B 組｜🟡 次要(給預設先跑,MVP 後可微調)

### B5. 規則內平行子項的次序
同一規則名下多行(如 tonogenesis 的 insert H / insert L)是同時評估還是依序?
- ⭐建議:**同時評估**(都以規則前狀態判斷),避免第一行改骨架影響第二行的條件判斷。`Then:` 複合各步仍依序(既有語意)。

### B6. 浮游自體段在 tier 內規則的可見性
tier 內規則的 selector `tone` 預設選不選得到浮游者?
- ⭐建議:**預設只見已聯結**,要見浮游須顯式 `tone&floating`——與 Scan 的 `over linked-only` 預設一致,全系統一條原則。

### B7. 局部性上界的精確度量
D9 預設 `syllable`,但「≤ 一個音節」怎麼算?
- ⭐建議:**「路徑跨越的音節界數 ≤ locality 所設層級對應的界數」**;`syllable` = 錨點同音節或相鄰音節(跨 ≤1 音節界)。邊界情形以界數計,不以物理距離計,確保確定性。

### B8. 動詞「無適用目標」行為
`dominate` 找不到可掛元音、`dock` 找不到空錨點、`associate` 目標不存在時?
- ⭐建議:**靜默略過 + info 級追蹤記錄**(不是 error,不是 warn)。與「規則完全不匹配即略過」的既有語意一致;需要嚴格時由 B5 分級表逐動詞提升。

### B9. 全域訊息分級表
把散落的各種回報統一成 error / warn / info 三級:
- ⭐建議草案:
  - **error(停止該詞演化)**:`strict-ncc: error` 時的 NCC;`on-unrealized-*: error`;型態括號缺失且規則強依賴。
  - **warn(記錄續跑)**:預設 NCC 違反;殘餘浮游 drop;`within stem` 因缺括號跳過。
  - **info(僅追蹤視圖)**:動詞無目標略過;lazy 重剖觸發點;暫態交叉已解除。
- 影響:一張表即可,MVP 內先按此,之後按實測調整。

## C 組｜🟢 Spell-out 語法控制

### C10. Spell-out 升級為宣告區塊
把現有三個 fallback 旗標擴為一個 `Spell-out:` 區塊,涵蓋多層壓平所需控制:
```
Spell-out:
    order      tone, nasal, atr        # 多層落同一音段的實現次序/優先(必需)
    empty      tone => M               # 殘餘 Ø 表層落值
    empty      nasal => bare           # 私有特徵殘餘 Ø = 不帶
    floating   tone => drop warn       # 殘餘浮游:drop|dock-to-edge|keep-mark|error
    contour    μ:{H L} => falling      # 多承載線性化為表層符號(必需)
    project    <syl> => stress-mark    # 韻律結構是否在表層留記號
    romanize-with  <romanizer-name>    # 拼讀後接的 romanizer
```
- ⭐建議:**採用區塊化**。`order` 與 `contour` 是「多對一壓平」與「圖→串造符」的核心,沒有它們多層落同一音段/輪廓調無定義,必須有。

### C11.（關鍵界線）Spell-out 是「翻譯層」還是「運算層」?
spell-out 裡能不能寫帶環境的改寫規則(如 downstep、clash 處理),還是只能寫查表式對應(圖樣 => 表層符號)?
- 選項:(a) **只允許查表對應**——左端圖樣、右端表層符號,無環境;真正需環境的表層音變前移為拼讀前最後一條 tier 規則;(b) 允許帶環境改寫,spell-out 自帶小型改寫語言。
- ⭐建議 **(a)**:spell-out 保持純「翻譯層」。理由同防 Scan 膨脹——不讓第二個規則系統長出來。後果:`clash tone H+H => downstep` 這類**不可**寫在 spell-out,必須是拼讀前一條普通規則。
- 影響:決定 spell-out 的複雜度天花板;是 C 組唯一有真取捨的一題。
