# 演化圖本體論(v0.1.1)— 模組 D

conlang 工作台的容器層:定義「一個語言節點是什麼」「演化如何被儲存與 replay」「方言/接觸/克里奧爾如何表示」。與 DSL 規格同哲學:**存事實(ChangeSet),表層狀態是 replay 的結果**。本檔涵蓋節點/邊、來源統一、克里奧爾、互通度/差異度,並全程標注實現梯次。

> **實現梯次圖例**:【M】= MVP 已定並實作 /【M+】= MVP 後 /【N】= v-next 留白(僅定接口或約束,不實作)。
> 每節標題附梯次;全文末 §9 有總表。

---

## 0. 核心洞見(統一原則)

**來源在操作上等價,只有程度區別。** 一個節點的 ChangeSet 本質是「對其入邊節點 ChangeSet 的引用+變換」。native(自身創新)、contact(借用)、fusion(克里奧爾)、simplification(簡化)並非四種機制,而是同一機制「引用了誰、引用多少」的不同程度——連續光譜,無需硬分類。此洞見使:來源標籤成為引用結構的**派生**(非原始資料)、多親成為引用數量的差異(非特殊結構)、自動演化只需調引用參數即可連續產出繼承→借用→融合→克里奧爾。

**鐵律**:資料層只存 ChangeSet 事實 + nativization 屬性;互通度、方言界線、pidgin/creole 顯示分類,皆為上層(UI / 模擬)對連續事實施加閾值/邏輯的**派生視圖**,永不回寫資料層。

---

## 1. 圖拓撲【M】

演化圖 = 有向圖,拓撲**預設為樹(單親)**,允許多親(融合)。

```
LanguageNode {
    id: NodeId,
    parents: Vec<NodeId>,          // 預設長度 1;多親是融合(克里奧爾),非特例結構
    changeset: ChangeSet,          // 本節點相對 parent(們)的內容(§3)
    nativization: Nativization,    // §4;獨立於 parents 結構
    pin: Option<UserLabel>,        // 使用者釘選/命名
}
```

**節點只在四種情形結晶**,其餘語言狀態是邊上的 replay 快照、按需計算不持久化(承 DSL 的 snapshot 哲學:中間形不存,replay 就有):
1. 分叉點(一狀態長出 ≥2 條不同縱向邊);
2. 接觸點(借用事件的端點);
3. 融合點(克里奧爾等多親節點);
4. 使用者釘選點(命名、檢視、手動編輯的起點)。

方言連續體因此**不是一堆節點**,而是節點之間 + 邊上 replay 的插值光譜;連續體只在分叉/接觸/釘選處結晶出節點。

## 2. 邊與來源:單一機制【M】

**只有一種邊:縱向(descent)。** 接觸不生特殊邊——借用 = 拉一個新節點,其 ChangeSet 含引用來源 X 的條目。橫向訊息下沉進「ChangeSet 如何生成」,圖拓撲保持樹形。(此為與早期三種邊模型的關鍵簡化,對齊 §0 洞見。)

多親融合是唯一的拓撲例外,僅在「結構性換源」(克里奧爾:詞彙與語法來自不同祖先)時啟用,由手動或 multi-agent 判定(§4),預設不啟用。

**無環約束(v0.1.1)**:ContactInjection 只能引用「時間上已 materialize」的節點狀態;引用圖必須無環(A 借 B、B 之後再借 A 合法——那是兩個不同時點的狀態,非循環)。

## 3. ChangeSet 與生成程序

### 3.1 MVP 樸素表示【M】

一個節點的 ChangeSet = 相對其 parent 的一串條目,**手動填寫**,不經生成程序:

```
ChangeSet = Vec<ChangeEntry>
ChangeEntry {
    op: ChangeOp,          // v0.1.2 定死:= docs/08 B1 的 L1 ∪ L2(小而穩、正交、原子)
                           //   L1 資料原語:Create/Delete/Modify/Split/Merge/Reference/SetTransparency
                           //   L2 語言原語:SoundChange/DeriveSense/Drift/Reanalyze/Fuse/
                           //               Adopt/Entrench/Attrit/Lexicalize/LexicalizeSense
                           //   L3 理論宏(Grammaticalization/Bleaching/…)非 op,是資料表(docs/08 L3)
    macro: Option<MacroId>, // v0.1.2:回指本 entry 所屬的 L3 宏,供回放顯示術語;
                            //   一個宏展開成多個 ChangeEntry,各自 macro 指同一 MacroId
    // source 不是獨立欄位:見 §3.2,由引用結構派生(Adopt 的 Reference 即來源)
}
// op 型別已於 v0.1.2 定死 = docs/08 B1(L1∪L2);D 只消費此 enum,不定義原語(單一資訊源)。
```

此表示足以支撐 M0–M2 的縱向演化與手動造語(含手動克里奧爾)。

### 3.2 來源 = 引用結構的派生【M 概念 / N 完整】

概念上,某條目的「來源」= 它實際引用了哪個 parent 的 ChangeSet:自身創新 = 不引用;contact-from-X = 引用 X 的子集並變換;fusion = 引用多個 parent。MVP 以 `ContactInjection(NodeId, …)` 顯式記錄引用,故來源可從中讀出;完整的「引用即來源、標籤全派生」待生成程序(§3.4)上線。

### 3.3 簡化/重新分析:併入語法化引擎,非獨立型別【M+】

丟失屈折、規則化、範疇合併——**不是獨立算子家族**,而是語法化引擎成熟後的自然副產品(reanalysis 本是語法化四機制之一;屈折丟失 = 型態→零的斜坡終點)。故 ChangeEntry **不為簡化預留獨立型別**;克里奧爾節點 MVP 階段的簡化內容**手動寫入**,自動生成待語法化引擎 + 其後。

### 3.4 生成程序:留白【N】

未來 ChangeSet 可由「存取入邊節點 ChangeSet 並經程序/語法糖生成」,使自動演化能連續調整引用程度。**本版留白**,但兩條約束現已鎖定:

- **內容層復用既有手動語法**:每個生成操作實際寫的規則,一律用既有 DSL(音變)/ 借詞改造規則 / 未來語法化手動語法——**不發明新內容語言**,全系統只有一套規則語言。
- **組合層待定**:最外層「引用/組合」算子(繼承哪個 parent、過濾哪些條目、引入誰)之語法,待自動演化 + multi-agent 需求明朗後定,或**直接借用其他成熟引擎的語法**(候選方向:語言 phylogenetics 工具、agent-based 語言演化框架)。候選草案(inherit / inherit-where / import-as-contact / create,filter 重用 selector)僅供參考,非定案。

## 4. Nativization:pidgin/creole 判定【M 結構 / M+ 湧現】

pidgin/creole 的分界是**社會語言學的——有無母語者**,不是入邊的結構分層。故為節點的獨立屬性,非由 parents 決定:

```
Nativization = None                 // 一般語言
             | Pidgin               // 接觸簡化系統,無母語者
             | Creole { generation } // pidgin 被某代當母語習得,獲完整語法
```

判定分工:一般造語**手動**填【M】;multi-agent 模擬中,系統偵測「無母語者的穩定溝通系統」→ Pidgin、下一代 agent 以之為習得起點 → Creole,是**湧現**結果【M+】;預設 None、單源。

此設計丟棄了早期「融合節點分層貢獻權重」的過度工程——融合的複雜性不在入邊怎麼分層,而在此單一屬性 + 節點自身 ChangeSet 的內容。

## 5. Replay 語意【M 即時 / M+ memoize】

一個節點的語言狀態 = 從 root 沿 parents 求值其 ChangeSet 序列(縱向:套規則;接觸:併入引用條目)。**多親節點的 MVP 語意(v0.1.1)**:以 `parents[0]` 為 replay 主幹,其餘 parent 僅供 ChangeSet 條目引用取材;完整融合 replay(多主幹混合)為【M+】。

- **預設即時 replay**【M】:狀態永遠是 ChangeSet 的函數,不存副本(單一資訊源)。與 M0 的 snapshot-and-actions 銜接——演化圖是「快照序列的樹狀推廣」,每條邊的 ChangeSet 就是一串 Action。
- **可選 memoize**【M+】:快取節點求值結果;parent 變動時沿依賴邊標 stale——與 lazy reparse 同構,實作思路復用。生成程序「只引用直接入邊」的限制(§3.4)保證依賴圖局部,stale 傳播不失控。

## 6. 差異度與互通度【M 分層對稱 / N 有向】

### 6.1 分層差異向量【M】

任意兩點(節點或邊上快照)的差異**不是單一數字**,而是**分層向量**——音系距離、詞彙距離、型態距離、句法距離各一分量(貢獻不同:詞彙差異最傷互通,規則性音變其次)。這直接依賴模組 C(分層結構檔)的「按層計算差異」能力;C 定義有哪些層、每層如何比對。

差異 = 兩點到共同祖先的 ChangeSet 距離的分層投影(差異是果,ChangeSet 是因)。**對齊鍵(v0.1.1)**:兩狀態的 sign 以 `SignId` 對齊(見 C §1)——同 id = 同一 sign 的兩個演化階段;無對應者計為生/滅。

### 6.2 互通度為派生函數【M 對稱 / N 有向】

```
intelligibility(a, b, contact_history?) -> scalar
```

- 【M】對稱版:忽略 `contact_history`,退化為分層差異向量的加權函數。確定、可即時算。
- 【N】有向版:互通度**不對稱**(A 懂 B ≠ B 懂 A,依接觸史與聲望)。待 multi-agent 上線,同一接口換實作、填入 `contact_history`,自然長出不對稱與趨同/分化動力學。

此「可替換函數」設計同 DSL 的 strategy 模組化(D28):本體不綁死「互通度怎麼算」,只定接口。

方言連續體 = 樹上一組互通度高於某閾值的鄰近點;閾值由觀察者/UI 設定,非本質——資料層不做此離散判斷(鐵律)。

## 7. 與其他模組的接口

- **← C(分層結構檔)**:§6 差異向量依賴 C 定義的層與各層比對法。**D 的下一步依賴 C 先細化。**
- **← M0 引擎**:§5 replay 復用 snapshot-and-actions;縱向 ChangeSet 的 SoundChange 條目即 DSL 規則 id。
- **→ multi-agent(Phase 2)**:§4 湧現判定、§6.2 有向互通度、§3.4 生成程序的引用參數,皆為 multi-agent 的操作對象。
- **→ 語法化引擎**:§3.3 簡化、Grammaticalization 條目型別的內容。

## 8. 十實例對照(D 相關者)

- **實例 8(借詞語言層)**:ContactInjection 條目;借詞層「新舊」= 條目在 ChangeSet 序列的插入位置(早期層被其後縱向音變 replay 到,晚期不會)。

## 9. 實現順序總表

| 梯次 | 項目 |
|---|---|
| **【M】MVP** | 圖拓撲(節點+入邊,預設單親)§1;單一縱向邊+接觸下沉 §2;樸素 ChangeSet(手動條目)§3.1;來源派生概念 §3.2;Nativization 結構+手動填 §4;即時 replay §5;分層差異向量 §6.1;對稱互通度 §6.2 |
| **【M+】MVP 後** | memoize + stale 失效 §5;簡化/重新分析(隨語法化引擎)§3.3;Nativization 的 multi-agent 湧現 §4;融合節點完整 replay |
| **【N】v-next 留白** | ChangeSet 生成程序組合層 §3.4(內容層復用既有語法已定;組合層待 multi-agent 或借用他引擎);來源標籤全派生 §3.2;有向互通度 §6.2 |

**依賴鏈**:D 的 §6(差異/互通度)依賴 **C 分層結構檔** 先定義層與比對法 → 下一個細化模組應為 C。生成程序(§3.4)依賴 multi-agent 需求明朗 → 最後。
