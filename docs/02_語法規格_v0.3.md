# Tier 音變 DSL — 語法規格(v0.3)

搭配架構書 v0.3 §4.1–4.2。本版在 v0.2 之上整併外部審查回饋與後續決策:**統一 selector 文法(骨架優先)、解析策略分家、葉子記法回歸音韻學傳統、四處語意釘死(spread 循序 / fill 建新 / dock tie-break / 調簇不透明)、lazy reparse**。

---

## 0. 決策記錄(design log)

v0.2 既有決策(D1–D14)全部沿用,此處僅列新增:

| # | 決策 | 內容 |
|---|---|---|
| D15 | selector 統一 | 一切皆 element;唯一組合子 `&`(交集)、`{}`(擇一)、量詞;狀態(Ø/floating/empty)是普通述語走 `&`,不設專用槽位 |
| D16 | 序數 | 統一尾槽 `[n]` `[first]` `[last]` `[n from right]`;只在韻律層 selector 或 Scan 塊內合法 |
| D17 | 策略分家 | `nearest`、tie-break 等「多候選怎麼挑」不是 selector,是動詞的 `strategy` 槽;dock 等距預設 `prefer-left` |
| D18 | 調簇不透明 | 粗掃描(along 比 anchor 粗)時每個刻度是一個不透明簇;scan 相鄰只算跨刻度,要進簇內就改細 `along` |
| D19 | 葉子清理 | 骨架優先統一;葉子換用不衝突符號並回歸音韻學通用記法:`#` 詞界、`[αplace]` 特徵變數(ASCII 別名 `[$place]`)、`$1` 專用於捕捉;Lexurgy 相容改由匯入轉換器承擔 |
| D20 | Scan 環境 | 塊內不另設 `where`;過濾即規則本身的環境槽 `/ _`(沿掃描軸解讀)。任意距離記號 `…` 為環境內合法元素,非獨立關鍵字 |
| D21 | spread 多來源 | 規則間嚴格循序,無同步語意;同步效果請以單一 `bidirectional` 規則表達 |
| D22 | fill 語意 | 對每個 Ø 錨點建立**獨立**自體段(非單一自體段延展);故 fill 後相鄰同值可再被 OCP 合併 |
| D23 | reparse lazy | 惰性重剖:唯讀查詢韻律結構時才更新;結構修復動詞(dominate/release)**不**觸發重剖,暫態病理結構(空莫拉等)得以存活至被利用 |
| D24 | Parse 定位 | Parse pattern 是有限 pattern language,非完整 CFG;ambisyllabicity、遞迴音步等需先放寬本體論(多支配),列為未來決策而非語法擴充 |
| D25 | aggregation | 分組/計數/多數決(如 majority rule)不塞入 Scan;留給未來明確的 aggregation 機制 |
| D26 | 動詞撞名 | `merge` / `delete` 跨韻律/旋律兩語彙共用名稱,**接受**:tier 使用前必先宣告、受詞 selector 型別足以消歧,且俗稱無直覺替代詞;文件加註,不另造詞 |
| D27 | dock 共同著陸 | 多個浮游自體段同拍選中同一空錨點 → **全部接上**(多承載本為合法狀態,即輪廓)+ info;同層多值若無 contour 對應,於 spell-out 檢查時報 **error** |
| D28 | strategy 模組化 | strategy 實作為獨立模組,所有動詞統一引用同一解析器;文法上 strategy 接受內建名或已註冊的自定義名,預留擴充空間 |

## 1. 本體論與不變式

(承 v0.2 §1,不變)表徵 = 骨架 + 韻律層(時間軌道,支配,有序)+ 旋律層(時間乘客,聯結,無序 + 固有序列)。純度不變式:條件可沿連結唯讀跨層(受**局部可達上界**,定義之唯一權威見《執行語意規格》§5:可達閉包,成分邊界 ∪ 錨定層相鄰一格,取聯集);寫只寫自己層;位置定址只在 Scan;整合只在末端 spell-out。

## 2. 記法慣例(回歸音韻學通用技法)

| 記號 | 意義 | 備註 |
|---|---|---|
| `A => B / C _ D` | 規則本體與環境 | `→` 為 `=>` 的合法同義寫法 |
| `_` | 變化位置 | SPE 傳統 |
| `#` | 詞界 | 取代 v0.2 的 `$`;`+` 保留給未來型態界 |
| `.` `\|` | 音節界、音步界 | |
| `[αplace]` | 特徵變數(同化) | α/β/γ 傳統記法;ASCII 別名 `[$place]` |
| `$1` `$.1` | 捕捉(音段 / 連音節) | `$` 自此**只**用於捕捉,一符一義 |
| `Ø` | 未指定(零特徵) | ASCII 別名 `0` |
| `*` | 刪除(結果側)/ 插入(匹配側) | 沿用 |
| `{ }` `&` `? + *n` | 擇一、交集、量詞 | selector 組合子(§3) |
| `:{H L}` | 簇內容匹配(有序,空格分隔) | 僅 Scan 塊內合法;與擇一 `{H,L}`(逗號)區分(§8) |

原則:每個符號恰一個意義;衝突時**音韻學傳統優先**,Lexurgy 慣例由匯入層轉換(§10)。

## 3. Selector(統一選擇子)

**一切皆 element。** 文字音段、`@class`、`[特徵矩陣]`、韻律單位 `<seg> <mora> <syl> <foot> <pword>`、旋律值(`H`、`+nasal`)、捕捉引用 `$1`——全是 element,全部用同一套組合:

```
selector := element ( "&" element )* ordinal?
element  := literal | @class | [features] | <level> | melody-val | {sel, sel, …} | (…)量詞
ordinal  := "[" (INT | "first" | "last") ("from" ("left"|"right"))? "]"
```

**狀態即述語(D15)。** `Ø`(空/未指定)、`floating`(浮游)、`empty`(結構空節點)、`linked`、`stressed`……都是普通 element,一律 `&` 交集,沒有專用冒號槽:

```
mora&Ø              # 無調莫拉
tone&floating       # 浮游調
<mora>&empty        # 結構空莫拉(待修復)
onset&[-voice]      # 清音節首
@vowel&[+long]&<syl>[last]    # 末音節的長元音(序數:韻律層合法)
```

**序數尾槽(D16)。** `<syl>[2 from right]`(倒數第二音節)、`mora&Ø[first]`(第一個無調莫拉)。合法性鐵律:序數只在(a)韻律層 selector(時間軌道內在有序,免費),或(b)Scan 塊內(旋律借軌道之序)。旋律層 selector 在塊外帶序數 → 編譯錯誤。

所有動詞、環境、Parse pattern 引用**同一套** selector 文法,不得各自重新定義。

## 4. 解析策略(Strategy)

「選哪個」(selector)與「多候選怎麼挑」(strategy)分家(D17)。strategy 是動詞的獨立槽:

```
strategy := ("nearest" | "leftmost" | "rightmost")
            ("prefer-left" | "prefer-right")?     # tie-break,預設 prefer-left
```

```
dock tone&floating strategy nearest              # 等距時取左(預設)
dock tone&floating strategy nearest prefer-right
```

`nearest` 自此不再出現於 selector 位置;v0.2 的 `dock … nearest` 寫法由此取代。strategy 是**開放集(D28)**:內建之外,可註冊自定義 strategy(實作於統一的 strategy 模組),文法上以名稱引用;所有動詞共用同一解析器,不得各自實作挑選邏輯。

## 5. 韻律層(時間軌道)— 支配語彙

宣告、Parse、結構動詞(parse / reparse / dominate / release / merge / delete)、`on-daughter-loss` 均承 v0.2 §2。更新兩點:

- **lazy reparse(D23)**:`reparse: lazy` 為預設。韻律結構在音段變動後標記為 stale;任何規則**唯讀查詢**韻律結構(讀 `<syl>`、`<mora>&[+heavy]` 等)時才即時重剖。**結構修復動詞不觸發重剖**——因此補償性延長裡的空莫拉可存活至 `dominate` 修復它。仍可顯式 `reparse <level>` 強制更新。
- **Parse 定位免責(D24)**:Parse pattern 為有限 pattern language(選項 `?`、量詞、擇一可用),非完整 CFG。ambisyllabicity、遞迴音步、appendix 等需先在本體論放寬「嚴格支配」,屬未來決策。

## 6. 旋律層(時間乘客)— 聯結語彙

宣告、表徵(聯結圖 + 序列)、`on-anchor-loss float`、`on-stray keep-in-place`、NCC 警告均承 v0.2 §3。宣告新增可選屬性 **`visible linked-only|all`**(預設 `linked-only`):控制該層自體段對規則的預設能見度——浮游者預設不被 selector 選中,須顯式 `&floating`;此屬性為通用可見性機制,未來擴充 extraprosodicity 之接口(B6)。動詞更新後全貌:

```
associate <melody-sel> -> <anchor-sel> [strategy …]
delink    <melody-sel> [from <anchor-sel>]
spread <值> <leftward|rightward|bidirectional>
       [blocked-by <selector>] [within <疆界>] [through] [on-conflict <值|stop|rule NAME>]
dock   <melody-sel>&floating <strategy>
shift  <n> <軌道單位> <方向>
merge  adjacent-equal
insert <值> floating [near <anchor-sel>]
delete <melody-sel>
fill   <層> Ø => <值> [within <疆界>]
```

**動詞撞名註記(D26)**:`merge` 與 `delete` 同名存在於韻律語彙(結構合併/刪節點)與旋律語彙(OCP 合併/刪自體段),以受詞 selector 型別消歧(`merge <mora><mora>` vs `merge adjacent-equal`;`delete <syl>…` vs `delete H…`);兩套語彙的其餘動詞維持互不重疊。

釘死的語意:

- **spread 多來源(D21)**:規則嚴格循序。`spread H` 整條跑完才輪 `spread L`;後者遇已佔(非 Ø)錨點依 D8 停下。任何「同時」效果以單一 `bidirectional` + `on-conflict` 表達。
- **fill(D22)**:對每個 Ø 錨點建立獨立自體段。若要單一自體段鋪開,請用 `insert` + `spread`。兩者在後續 OCP/delink 行為不同,是刻意區分。
- **on-conflict** 可引用具名規則(`on-conflict rule resolve-by-stress`),MVP 內先支援值與 stop。
- 讀取為可達性自推(D9);局部可達上界的定義以《執行語意規格》§5 為唯一權威(預設 `locality syllable`,參數可改)。

## 7. 疆界與型態括號

承 v0.2 §4:`within` 與 anchor 正交;pword/foot 由剖析而得隨時可用;stem/root 由型態層括號餵入、音系唯讀,缺括號時相關規則報警告。

## 8. Scan(全域位置存取)

```
Scan <melody> along <prosodic-level> [within <疆界>] [from left|right] [over linked-only|all]:
    <塊內規則>          # 過濾由規則自身的環境 / _ 承擔,沿掃描軸解讀
```

- 三道鎖與 `over` 語意承 v0.2 §5(D3/D4);塊內「相鄰」= 沿掃描軸序列相鄰(D5)。
- **調簇不透明(D18)**:`along` 比該旋律層 anchor 粗時(如 tone 錨 mora、along syllable),每個刻度報告一個**不透明簇**(該單位下所有聯結值的有序子列)。跨刻度相鄰不進入簇內;`H` 與同音節內的 `L` 不算 scan 相鄰。要簇內操作,改 `along mora`。簇可整體匹配:`<syl>:{H L}`(帶降調簇的音節)。
- **環境即過濾(D20)**:塊內不設獨立 `where`——想過濾枚舉序列,就用規則本身的環境槽 `/ X _ Y`,在塊內沿**掃描軸**解讀(X、Y 是序列上的前後項)。`…` 表序列任意距離,是環境內的合法元素:

```
# Meeussen:序列相鄰 H…H,後者變 L
Scan tone along mora within pword from left:
    H => L / H _

# 第二個 H 之後的第一個 L 降級
Scan tone along mora within pword from left:
    L[first] => M / H[2] … _         # … = 序列任意距離(環境內合法元素)

# 指派 H 到第一個無調莫拉
Scan tone along mora within pword from left:
    associate H -> mora&Ø[first]
```

刻意不給:`find` / 分組 / 遞迴查詢 / aggregation(D25)。「第一組 HH」「多數決」類需求留給未來明確機制,Scan 保持小盒子。

## 9. Spell-out(末端整合)

唯一整合點,置於全流程末端;中間階段用快照拼讀(不改動表徵)。**語法與語意之唯一權威為《執行語意規格》§6**:Spell-out 是純函數(Representation → Surface,僅 lookup / flatten / render),以宣告區塊(order / empty / floating / contour / project / romanize-with)控制,取代 v0.2 的三個 fallback 旗標。需要環境的表層音變請前移為拼讀前最後一條普通規則。

## 10. Lexurgy 相容性(匯入層)

手寫語法**不**追求百分百相容;相容價值(搬運社群規則庫)由匯入轉換器承擔。葉子對照:

| Lexurgy | 本 DSL | 說明 |
|---|---|---|
| `$`(詞界) | `#` | 音韻學傳統 |
| `[$place]` | `[αplace]`(別名 `[$place]`) | α 記法為正典 |
| `$1` `$.1` | `$1` `$.1` | 不變,`$` 專用於捕捉 |
| `Feature (syllable) x` | `Feature (syllable) x` | 不變 |
| floating diacritic | `Melody … anchor …` | 語意升級:轉換器將浮游變音符提升為旋律層 |
| 組合子 `& {} ? + *` | 相同 | 骨架本就一致(D15 即師法其 element 統一) |

## 11. Pseudo-EBNF(增量)

```
selector   := element ("&" element)* ordinal?
element    := LITERAL | "@"NAME | "["feat+"]" | "<"LEVEL">" | MELODY-VAL
            | "{"selector(","selector)*"}" | "("pattern")"QUANT?
            | "Ø" | "floating" | "empty" | "linked"
ordinal    := "["(INT|"first"|"last")("from"("left"|"right"))?"]"
strategy   := ("nearest"|"leftmost"|"rightmost"|NAME)("prefer-left"|"prefer-right")?   # NAME=已註冊自定義(D28)
env        := (selector | "…")*          # 規則環境;… 僅 Scan 塊內合法
melody-verb 增補: "dock" selector strategy | "fill" NAME "Ø" "=>" VAL ("within" UNIT)?
             | spread … ("on-conflict"(VAL|"stop"|"rule" NAME))?
melody-opt 增補: "visible" ("linked-only"|"all")   # 預設 linked-only(B6)
global-param 增補: "reparse" ("lazy"|"manual")     # 預設 lazy
```

## 12. 範例集(記法更新版)

```
# 8.1 聲調產生(#、fill 建新自體段)
Melody tone {H, M, L} anchor mora    # 字母表含 M(修正 v0.2 宣告 {H,L} 卻 fill M 的矛盾)
tonogenesis:
    insert H floating near mora / onset&[-voice] _
    insert L floating near mora / onset&[+voice] _
dock-tone:    dock tone&floating strategy nearest
devoicing:    [+voice]&onset => [-voice]
fill-default: fill tone Ø => M within pword      # 每個 Ø 各建一個 M(D22)
ocp-cleanup:  merge adjacent-equal               # 相鄰獨立 M 可在此合併

# 8.3 穩定 + 位移(浮游留原位 (H)@n)
final-vowel-loss: @vowel => * / _ #
redock:           dock tone&floating strategy nearest prefer-left

# 8.4 補償性延長(lazy reparse 保住空莫拉)
coda-loss:   @coda => * / @vowel _ .
repair-mora: dominate <mora>&empty -> @vowel leftward   # 結構動詞,不觸發重剖(D23)

# 8.5 ATR 雙向(循序 + 衝突)
atr-spread: spread +ATR bidirectional within stem on-conflict stop

# 8.6 Bantu(Scan + 序數尾槽)
Scan tone along syllable within pword from right:
    associate H -> <syl>[2]                       # 倒數第二音節
Scan tone along mora within pword from left:
    H => L / H _                                  # Meeussen(環境沿掃描軸)
    associate H -> mora&Ø[first]                  # 第一個無調莫拉
```

## 13. FST 邊界與開放問題

- 可編譯性分層承 v0.2:旋律規則(locality 內)≈ 正則;Scan 與 spell-out 為標記非正則點,永久直譯器。
- feature geometry(D13)、aggregation(D25)、本體論多支配(D24)、extraprosodicity(暫緩)為已知 MVP 外邊界。
- 新開放項:環境內 `…`(任意距離)的複雜度上界(建議每條環境限一個 `…`);匯入轉換器對 Lexurgy `Else:` 階層與 `defer` 的映射完整性。
