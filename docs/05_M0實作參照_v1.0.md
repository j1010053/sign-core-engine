本檔是 M0(引擎原型,無 UI)的單一實作參照,整併六題技術問答之結論。規範性上游:《執行語意規格 v0.1》(怎麼跑)、《語法規格 v0.3》(能寫什麼)、《架構書 v0.3》(全局)。衝突時以上游為準;本檔只新增實作層決策。

- **哨兵規則**:實作過程中若發生「逐檔/逐函式翻譯 Lexurgy 原始碼」的行為,直接向專案擁有者告知,不需事先確認。Rust 與 Kotlin 架構差異大,最優寫法下自然不構成翻譯;此規則是保險絲,不是常態流程。

## 1. 核心法則(全程適用)

### 1.1 四條實作原則(=《執行語意規格》§9)
1. **不重複造輪子**:動工前盤點開源模組(§6 清單);採用前驗證授權與維護狀態。
2. **基礎先行**:先實作原語,具名動詞一律由原語組合——旋律 `associate/delink/insert/delete` 為原語;`spread`=迭代 associate、`dock`=條件 associate、`shift`=delink+associate、`fill`=逐 Ø insert+associate、`merge`=delete+associate;韻律 `dominate/release` 為原語,`parse`=批次 dominate。
3. **單一資訊源**:每個 identity 恰一個權威存放處——邊只在聯結表、序列位置只是 seq 索引、韻律只在 Span 序列、stale 只在旗標;文件同理(概念定義唯一,其餘引用)。
4. **功能完整下精簡**:以驗收測試(§8)界定完整;優先刪抽象層而非加。

### 1.2 可移植性規範(WASM-safe core)
核心 crate 內:
- 禁多執行緒(詞極小,單詞平行無收益;詞典級平行留殼層,未來 rayon + feature flag)。
- 禁 `std::fs`(核心只吃 `&str`/bytes,IO 在殼層)。
- 禁 `panic!` / `println!`:錯誤走 `Result<T, EngineError>`(thiserror);診斷(warn/info/trace)是**回傳資料**非列印——與警告分級系統(執行語意 §7)同構。`debug_assert!` 限內部不變量。
- 禁 `std::time::Instant` / `SystemTime`(wasm32 上 panic;計時在殼層)。
- 禁環境隨機源(不用 `thread_rng`;一律注入 seeded PRNG,`rand_chacha`)——同時是可重現性要求。
- **制度化**:CI 掛 `cargo build -p core --target wasm32-unknown-unknown`,規範違反 = 紅燈,不靠紀律。

## 3. 表徵方案:snapshot-and-actions

**「凍結快照 + Action 清單 + commit 重建」**,逐字實現執行語意 §1 生命週期:Parallel Match 在凍結 `Word` 上跑 → Action Evaluation 產出 `Vec<Action>` → Commit 套用產生新 `Word` → Validation(NCC 等)→ Lazy Reparse 標記。

> **`Word` 的地位(《架構修補01》P1)**:`Word` 是**臨時韻律域**——由 sign 組合按需建構(預設 ω,sandhi 擴至 φ/ι/U),非儲存單位;表層形按需導出、永不儲存。M0 內以測試/CLI 手造 `Word` 等價於「已建構完成的臨時韻律域」,結構定義不變。

```rust
struct Word {
    skeleton: Vec<Seg>,               // Seg { sym: SymId, feats: FeatBits(u64) }
    prosody:  ProsodyLayers,          // 每層 Vec<Span>;Span=對下層的連續區間+層級特徵
    melodies: Vec<MelodyTier>,        // MelodyTier { alphabet, seq: Vec<Autoseg>, visible, policies }
    morph:    Vec<Bracket>,           // stem/root 括號,唯讀
    stale:    StaleFlags,
}
struct Autoseg { val: ValId, links: SmallVec<[AnchorRef; 2]> }   // links 空=浮游;seq 索引=序列位置
enum Action { Associate{..}, Delink{..}, Insert{..}, Delete{..}, Dominate{..}, Release{..} }
```

設計要點:
- **快照 = clone**:詞僅數十音段,整詞 clone 便宜;trace / undo / 演化樹回放免費;不用 persistent 結構、不用 `im`。
- **韻律不用一般圖**:嚴格分層+相鄰+全覆蓋 ⇒ 每層是「對下層的連續 Span 序列」,良構由結構保證;NCC 只需檢查旋律聯結。**不引 petgraph**。
- **AnchorRef = 層級+索引**:commit 是序列點,規則內索引凍結、commit 時重編;**不用 slotmap**。
- **Interning**:符號/值進引擎即 `SymId`/`ValId`(整數),特徵為 bitset;IPA 字串只存在於 parse 入口與 spell-out 出口。
- **與 Lexurgy 結構必異的三處**:浮游變音符(它=音段旗標;我們=獨立 tier 自體段)、音節(它=逐音段標注;我們=Span,才有空莫拉與 dominate)、捕捉 `$1`(它=字串切片;我們=骨架索引區間+隨附聯結,`$.1` 才搬得動掛著的調)。
- **Strategy 模組(D28)**:單一解析器 `fn resolve(candidates, ward, tiebreak) -> Option<AnchorRef>`;動詞不得自帶挑選邏輯;自定義 strategy 以名稱註冊。

## 4. DSL 前端

- `logos` lexer:token 化前先 `unicode-normalization` 正規化(NFC/NFD 的變音符坑:ã 一碼 vs 兩碼,必踩,入口統一)。
- `chumsky` parser:錯誤恢復與診斷品質是產品的一部分(使用者會寫錯規則);輸出型別化 AST。
- **Lexurgy .g4 當參照規格**:沿用部分的優先序/結合性/空白處理照抄其文法定義(非其實作)。

### 沿用 vs 擴充(對照《語法規格》§10)
| 沿用(照 .g4 對齊) | 擴充(我們的新文法) |
|---|---|
| Feature/Symbol/Diacritic/Class/Element 宣告 | Prosody / Parse / Morae: / Feet: |
| `& {} ? + *n`、`=> / _`、`//` | Melody … anchor … visible … |
| `$1` / `$.1`、特徵變數(改 `[αplace]`) | 聯結動詞 ×9 + 結構動詞 ×2 |
| Then: / Else: / defer / cleanup | Scan 塊、Spell-out 區塊、strategy 槽 |
| strata、Syllables: onset::nucleus::coda | `Ø`、序數尾槽 `[n]`、`#` 詞界(原 `$`) |

## 7. 測試策略

1. **單元**:六原語各自的不變量(proptest:剖析後全覆蓋、commit 後 NCC 檢查完備、associate 後浮游數守恆…)。
2. **快照**:insta 對「每 commit 一快照」;驗收 = 語法規格範例集 8.1–8.6 的逐步推導快照。
3. **Lexurgy 語料黑盒**:corpus submodule + harness(.lsc → 匯入轉換器 → 引擎 → 比對);**分歧白名單**必備——預期不同的案例標注「原因 + 決策編號」(浮游存亡→D14、套用模型→A1、詞界符→D19),紅燈才分得清 bug vs 設計差異。前置:轉換器需先補 `Else:`/`defer` 映射(語法規格 §13 開放項)。
4. **可移植性**:CI wasm target(§1.2)。

## 8. M0 里程碑與開發順序

驗收定義:**六原語 + 生命週期正確,範例集 8.1–8.6 全數通過快照測試,經 CLI 可以(規則檔 + 詞表)→ 導出驗收。**(《架構修補01》:「詞表批次演化」表述改為導出;M0 的批次跑之後改寫為 AddRule + 立即 Lexicalization 相容模式,見修補 §3 步驟 8。)

1. `repr/`:資料結構 + interning + clone 快照——原則 3 的第一次真正考驗(每 identity 一個家)。
2. `primitives/` + `lifecycle/`:六原語 + match→eval→commit→validate;proptest 不變量上線。
3. `verbs/` 第一批:insert/dock/fill/merge(全組合式)→ **範例 8.1(tonogenesis)綠燈** = 第一個里程碑。
4. `dsl/`:lexer+parser 到能解析 8.1 的規則檔;CLI 串起 end-to-end。
5. `verbs/` 第二批(spread/shift)+ `locality/` + stability/lazy-reparse → 8.2–8.5 綠燈。
6. `scan/` + `spellout/` → 8.6 綠燈,M0 收工。
7. (M0 尾聲)Lexurgy harness 骨架 + 白名單初版,為 M2 匯入器鋪路。

順序原則:每一步都以「哪個範例綠燈」為出口,不做無測試出口的階段。
