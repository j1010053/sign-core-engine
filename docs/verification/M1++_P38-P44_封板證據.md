本表只以《架構修補彙整 05–11》§1 的 P38–P44 為規範權威；《架構修補07》保留詳細理由。

回歸護欄；一個 parser 測試或表層字串不單獨算完成證據。

## 執行契約

- 表徵：`Language`/`SignDef`/單一 `OntologyRegistry`/四維 `Defs`/`DerivedToken`。
- 選擇：分類 guard 讀該求值單元的 belongs 閉包；欄位 guard 讀當前維度 live state。
- 轉換：同維規則順序 commit；Else first-matching；Then feeding，Error 後停止。
- 衝突：遠祖先、近祖後；同距離後寫 `belongs` 勝；本地最後；菱形只展開一次。
- 觀察：`ValidationReport`、`RuleRecord`、phon source map、token provenance、phon steps。
- 公共路徑：`.lang → compile_system → filler rules → construction → token rules →
  Tshiatūn phon runtime → surface/trace`。
- 時間：本階段只有共時 derivation step；無 usage event、歷史切片或 population update。

## 封板閘門

執行 `scripts/verify-m1pp.ps1`。腳本先做 submodule/toolchain preflight，再跑 fmt、Clippy、
M1++ 指名測試、language 全測試、Tshiatūn 全測試與 `tshiatun-core` WASM build。
exit 0=全部通過、exit 1=格式／lint／測試／build 失敗、exit 2=工具或 submodule 缺件。
摘要寫入 `target/verification/m1pp-summary.json`。

2026-07-22 Step 13 語義／API 封板回歸為根 workspace **251/251**（language 220、changeset 31）、Tshiatŭn **157/157**，皆為
0 failed／0 ignored／0 filtered。當日本機 GNU toolchain 的一鍵閘門在 preflight
正確以 exit 2 停止：Clippy 已安裝於 MSVC toolchain，但該環境缺 MSVC linker／Windows SDK libraries；
可正常測試的 GNU toolchain 沒有其專屬 rustfmt／Clippy components，且主機未安裝
`wasm32-unknown-unknown` target。因此
這組回歸數是 runtime 證據，不是 fmt／lint／WASM 全閘門 exit 0 的宣稱。

後續 M1+ 稽核曾發現 direct stored filler 與 derived-token downward forwarding 的
能力邊界；相關共時 runtime 已以 deep baseline、frozen probe 與 contextual filler-rule
重跑補齊，證據見 `slot_feature_bindings.rs` 與 docs/19。它不屬於 Step 14 ChangeSet
封板，也不倒推為早期 P38–P44 測試已曾覆蓋。
